# RCoder - AI-Powered Development Platform

> [中文文档](README.md)

RCoder is a modern AI-powered development platform built with Rust. It provides unified access to multiple AI agents (Claude Code, Codex, etc.) through the **ACP (Agent Client Protocol)**, and ships with complete **UserApp application management** (dev/prod environments, build & release pipeline, idle recycling). The project uses a **microservice architecture** with **Docker and Kubernetes dual runtimes** and **high-performance gRPC communication**.

## ✨ Features

- 🤖 **Multi-Agent Support** - Unified access to Claude Code, Codex and other agents via the official ACP SDK (`agent-client-protocol v2`, wire-compatible with all ACP v1 agents)
- 🐳 **Dual Runtimes** - Docker Compose (local development) and Kubernetes (production: StatefulSet + per-agent PVC + CephFS) from the same codebase
- 📦 **UserApp Management** - dev/prod environments, build & release pipeline, file/log/storage management, idle recycling with traffic-based wake-up, full deletion
- 🔁 **Reverse Proxy** - Integrated Cloudflare Pingora for high-performance port routing and UserApp sub-path proxying
- 🌐 **HTTP API** - Axum-based REST API with unified SSE progress streaming; OpenAPI docs auto-generated by utoipa (Swagger UI + Scalar)
- ⚡ **gRPC Communication** - High-performance internal communication via Tonic with Server Streaming for real-time progress
- 🖥️ **Computer Agent** - Containerized AI agent environment with VNC remote desktop, audio streaming, and IME input
- 🧩 **Pluggable Storage** - In-memory backend (default) and PostgreSQL backend (K8s variant), switched via Cargo features
- 📊 **Observability** - Tracing + OpenTelemetry distributed tracing + dial9 event-level Tokio tracing
- 🔒 **Safety Guardrails** - Workspace-level lints forbid `unsafe` code and `unwrap/expect` in production paths

## 🏠 Architecture Overview

### Overall Architecture

```
External Client (HTTP/SSE)
    ↓
RCoder (HTTP API Server + Container Management + gRPC Client)
    ↓ gRPC (Chat, CancelSession, SubscribeProgress)
Agent Runner (gRPC Server in container/Pod)
    ↓ Server Streaming (real-time progress events)
RCoder (converted to SSE)
    ↓
External Client (SSE)
```

### Core Components

- **RCoder Main Service** - Axum HTTP assembly + container orchestration + gRPC client + embedded file-server
- **Agent Runner** - Containerized AI agent runtime providing gRPC services and driving ACP connections
- **App Manager** - Full UserApp lifecycle (dev development environment / prod runtime environment)
- **Pingora Proxy** - High-performance reverse proxy (port routing + UserApp application proxy)
- **Docker Manager** - Container lifecycle management (Docker / K8s dual-backend abstraction)

### 🛠️ Tech Stack

| Category | Technology | Description |
|----------|-----------|-------------|
| **Language** | Rust 2024 Edition (1.85+) | MSRV 1.85 (minimum for edition 2024) |
| **HTTP Framework** | Axum 0.8 + Tower | High-performance async web framework |
| **RPC Framework** | Tonic 0.14 | High-performance gRPC (all-rustls) |
| **AI Protocol** | agent-client-protocol v2 + MCP (rmcp) | Official ACP SDK, v1 wire-compatible |
| **Containerization** | Docker (Bollard) + Kubernetes (kube-rs) | Dual runtime abstraction |
| **Persistence** | PostgreSQL (SQLx, feature-gated) / in-memory | PG for the K8s variant; Docker path has zero dependencies |
| **Logging** | Tracing + OpenTelemetry | Structured logging (file-based daily rotation under K8s) |
| **Profiling** | dial9 + hotpath | Event-level Tokio tracing (local dev) + function profiling |
| **API Docs** | utoipa + Swagger UI + Scalar | OpenAPI auto-generation |

## 🚀 Getting Started

### 📝 Prerequisites

- Rust 1.85+ (2024 Edition)
- Docker (local Docker Compose mode) or a K8s cluster (devspace, OrbStack recommended)
- Optional: Claude Code CLI (for the Claude agent)

### 🛠️ Installation & Running

#### Local Development

```bash
# Clone the repository
git clone https://github.com/nuwax-ai/rcoder.git
cd rcoder

# Build the whole workspace
cargo build --workspace

# Run the main service (default port 8087)
cargo run --bin rcoder

# Specify port and projects directory
cargo run --bin rcoder -- --port 8087 --projects-dir ./my-projects
```

#### Docker Compose Development Mode (Recommended, port 8090)

```bash
# First deployment: build images + start containers
make dev-build    # Build Docker images
make dev-up       # Start containers (main service 8090 / Pingora 8089)

# Daily development: hot-recompile in seconds after Rust changes
make dev-hot      # Recommended! Incremental <2min, no full rebuild needed

# Full rebuild (only needed when Dockerfile / Cargo.toml deps / non-Rust files change, 10+ min)
make dev-restart

# Logs / stop
make dev-logs
make dev-down
```

#### Local K8s Mode (devspace + OrbStack, port 8290)

```bash
# Initialize and start (namespace: rcoder-dev)
make devspace-init
make devspace-dev

# Health check
curl http://127.0.0.1:8290/health
```

> ⚠️ Under K8s/devspace mode, rcoder logs are **written to files, not stdout** (`/app/logs/rcoder.YYYY-MM-DD`, JSON format). An almost-empty `kubectl logs` output is expected.

#### Enable Reverse Proxy

```bash
# Enable the Pingora reverse proxy
cargo run --bin rcoder -- --enable-proxy --proxy-port 8080

# Specify the default backend port
cargo run --bin rcoder -- --enable-proxy --proxy-port 8080 --backend-port 3000
```

### 💻 CLI Arguments

| Argument | Short | Description | Example |
|----------|-------|-------------|---------|
| `--port` | `-p` | Main service port | `--port 8087` |
| `--projects-dir` | `-d` | Project workspace directory | `--projects-dir ./projects` |
| `--enable-proxy` | `-e` | Enable Pingora reverse proxy | `--enable-proxy` |
| `--proxy-port` | - | Pingora listen port | `--proxy-port 8080` |
| `--backend-port` | - | Default backend port | `--backend-port 3000` |

```bash
# View all arguments
cargo run --bin rcoder -- --help
```

## 📚 API Reference

The **authoritative** API definition is the runtime-generated OpenAPI documentation: after startup, visit `/api/docs` (Swagger UI and Scalar views, main + file-server docs) for the full contract of every endpoint.

Core entry points (see the concept docs for each domain):

| Entry | Domain |
|--------|--------|
| `POST /chat` + `GET /agent/progress/{session_id}` (SSE) | AI session main chain ([Sessions & SSE](docs/concepts/agent-sessions.md)) |
| `/api/v1/userapp/*` | UserApp management ([concepts](docs/concepts/userapp.md)) |
| `/computer/*` | Computer Agent: VNC/audio/IME containerized environment |
| gRPC `AgentService` | rcoder ↔ agent_runner internal communication ([gRPC](docs/architecture/grpc.md)); proto at `crates/shared_types_grpc/proto/agent.proto` |

### 💬 Usage Examples

```bash
# Health check
curl http://localhost:8087/health

# Chat
curl -X POST http://localhost:8087/chat \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": "Hello, please help me create a Rust Web API project",
    "project_id": "my-project"
  }'

# Real-time progress stream
curl http://localhost:8087/agent/progress/your-session-id \
  -H "Accept: text/event-stream"
```

## ⚙️ Configuration

### Priority Order

1. **CLI arguments** - highest priority
2. **Environment variables** - medium priority
3. **Config file** (config.yml, auto-generated/mounted) - lower priority
4. **Defaults** - lowest priority

### Config File Example (excerpt, full version at [docker/config.yml](docker/config.yml))

```yaml
# Default AI agent type (Claude/Codex)
default_agent: "Claude"

# Project workspace directory
projects_dir: "/app/project_workspace"

# Main service port (overridden by RCODER_PORT)
port: 8090

# Container cleanup configuration
cleanup_config:
  enabled: true
  idle_timeout_seconds: 600
  cleanup_interval_seconds: 500
  docker_stop_timeout_seconds: 30
  container_protection_seconds: 300

# Pingora reverse proxy configuration
proxy_config:
  listen_port: 8088
  default_backend_port: 8090
  backend_host: "127.0.0.1"

# Docker configuration (multi-image + per-service resource limits;
# under K8s this feeds Pod resources)
docker_config:
  multi_image_config:
    ...

# Port-60000 file-server routing proxy (dev form)
file_server_proxy:
  listen_port: 60000
  rust_upstream_port: 8090
  ts_upstream_port: 60001
  policy: all_rust
```

### Environment Variables (common)

| Variable | Description | Default |
|----------|-------------|---------|
| `RCODER_PORT` | Service port | 8087 |
| `RCODER_PROJECTS_DIR` | Projects directory | ./project_workspace |
| `RCODER_STORAGE_BACKEND` | Storage backend (memory/postgres) | memory |
| `DOCKER_SOCKET_PATH` | Docker socket path | /var/run/docker.sock |
| `RCODER_DOCKER_IMAGE` etc. | Custom image configuration | - |

## 🔧 Development Guide

### Running Tests

```bash
# Whole workspace: nextest, all features, collects all failures
make test

# Single crate
make test NEXTEST_ARGS='-p app_manager'

# Default-feature regression / standalone app-cli / doc tests
make test-default
make test-app-cli
make test-doc

# Serial run of workspace + app-cli + doc tests; any failure fails the whole run
make test-all

# Local Docker Compose core-business integration regression
make test-e2e
```

Requires `cargo-nextest` (`cargo install cargo-nextest --locked`). `make test` equals `cargo nextest run --workspace --no-fail-fast --all-features`; use `TEST_FEATURES=` to switch to default features and `NEXTEST_ARGS` to pass nextest filters.

`test-all` does not include Compose/K8s E2E and does not replace default-feature regression. `make test-e2e` verifies core business chains through a dedicated strict launcher; see the [E2E guide](tests-e2e/tools/README.md) for prerequisites.

### Code Quality

```bash
# Format
cargo fmt

# Lint (workspace currently zero warnings, incl. -D unsafe_code / await_holding_lock)
cargo clippy --workspace --all-features --tests
```

### Daily Development Rhythm

```bash
# Docker Compose mode: code change → hot recompile in seconds
make dev-hot

# K8s/devspace mode: sources sync automatically, but the rcoder process
# needs a restart to pick them up (in-container /app/dev-rcoder.sh restart, ~1min incremental)

# Run locally
RUST_LOG=debug cargo run --bin rcoder -- --port 8087
```

## 🚀 Deployment

Full guides for the three deployment forms: [Docker Compose](docs/deployment/docker.md) (recommended locally, incl. `dev-hot` hot recompile), [Kubernetes](docs/deployment/kubernetes.md) (production: Agent Runner as STS + per-agent PVC — stopping never deletes the volume, OOM self-heals at container level; UserApp prod as Deployment + per-app PVC), [Host machine deploy-host](docs/deployment/host.md) (single-machine desktop base form).

```bash
# Image builds
make docker-build                  # Full
make docker-build-master           # Main service image
make docker-build-agent-runner     # Agent Runner image
make docker-build-agent-production # Production image (no debug tools)
make docker-build-app-runtime      # UserApp runtime image (multi-language unified)

# Local K8s development
make devspace-dev
```

For performance diagnostics (dial9 event-level Tokio tracing): `make dial9-on` / `dial9-off` / `dial9-view` — see the [Observability Guide](docs/observability.md).

## 🐛 Troubleshooting

### Common Issues

- **Port already in use** - use `--port` to pick another port
- **Container startup failure** - check the Docker service status and network configuration
- **gRPC connection failure** - verify container network and port configuration (under K8s: `{pod}-svc.{ns}.svc.cluster.local:50051`)
- **Empty `kubectl logs` under K8s** - expected; rcoder logs go to `/app/logs/rcoder.YYYY-MM-DD` inside the pod (daily-rotated JSON)
- **API Key errors** - check the `api_key_auth` configuration

### Debug Mode

```bash
# Verbose logging
RUST_LOG=debug cargo run --bin rcoder

# Container logs
make dev-logs

# Enter the container
docker exec -it <container_id> /bin/bash

# Test an ACP agent locally (no full service needed)
cargo run -p rcoder-cli
```
