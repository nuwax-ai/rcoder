# 8. 带数据库的应用部署(PostgreSQL + dbx + ttyd)

> ⚠️ **本文示例仍为 v1 create 链路（`POST /api/v1/userapp` 已删除）**——镜像/端口/探针/命令
> 已全部平台内定。当前正确链路见 `06-快速开始`（六步编排）与 `02-接口手册`
> （`POST /apps/{id}/start` 统一部署入口）。下文保留仅作概念参考，接口调用方式以 06/02 为准。
>
> 🔄 **pgweb 已退役**——数据库 Web 控制台统一由 **DBX** 承担（面板免登 + local-pg 预置连接
> 开箱即用；沙箱内 AI agent 另可通过 dbx MCP 零配置查库）。

> UserApp 部署的应用,**容器内自带** PostgreSQL + dbx(Web UI 操作数据库)+ ttyd(命令行终端),经 pingora path 路由访问,PG 数据持久化到 workspace(删容器不丢)。
>
> ✅ 实测环境(Docker Compose 模式):rcoder `@8090` API / `@8089` pingora。

## 概述

`app-runtime-*` 镜像(node/java/python/go/rust)单容器打包:

| 进程 | 端口 | 用途 | 对外 |
|---|---|---|---|
| 用户应用 | 用户端口(如 3000) | 用户 command | HTTP(pingora)|
| **dbx** | 4224 | DBX 数据库 Web GUI(60+ 数据库) | HTTP(pingora)|
| **ttyd** | 7681 | 命令行终端(/app 目录)| HTTP(pingora)|
| **PostgreSQL** | 5432 | 数据库(应用 + dbx 访问)| 仅容器内/集群内(TCP)|

入口 `start-app.sh`(ENTRYPOINT):supervisor 管理固定服务(PG/dbx/ttyd/file-server-proxy)+ 用户服务;PG 初始化 + 数据落 `PGDATA`(workspace 持久化)。

## 访问(经 pingora path 路由)

| 服务 | URL |
|---|---|
| 用户应用（pingap 统一入口，免端口） | `http://{pingora}:8089/api/v1/userapp/proxy/app/prod/{user_id}/app-myapp/` |
| **dbx** | `http://{pingora}:8089/api/v1/userapp/proxy/dbx/prod/{user_id}/app-myapp/` |
| **ttyd** | `http://{pingora}:8089/api/v1/userapp/proxy/ttyd/prod/{user_id}/app-myapp/` |

浏览器:
- **dbx** → 面板免登直开;**local-pg 预置连接开箱即用**(unix socket 免密直连容器内 PG,与 PG
  密码解耦,改密无感),双击连接即查表/跑 SQL;需要连外部库时手动 Add Connection
- **ttyd** → 直接进入命令行(/app 目录),可 `psql`、`node`、排查

## PG 连接

| 场景 | 连接串 |
|---|---|
| 应用(容器内) | `postgresql://app:secret123@localhost:5432/myapp` |
| 应用(K8s 集群内) | `postgresql://app:secret123@app-myapp-svc:5432/myapp` |
| dbx UI | local-pg 预置连接免填(socket 免密);手动连接填 host=localhost port=5432(同凭证)|
| ttyd 命令行 | `psql -h localhost -U app -d myapp` |
| AI agent(沙箱) | dbx MCP(`dbx-mcp-server`,经免登 dbx-web,零配置) |

## 数据持久化

PG 数据落 PGDATA(UserApp workspace 持久化目录):
- **Docker**:bind mount workspace → 容器,pgdata 子目录持久
- **K8s**:per-app PVC,数据子目录持久
- **删容器(purge=false)**:PG 数据保留;同 `app_id` 重建自动挂回(误删找回)
- `purge=true` 才清空

> 验证:删容器 → PGDATA 文件留在卷 → 重建(同 app_id)→ `start-app.sh` 检测 PG_VERSION 跳过 initdb → 数据原样恢复。

## 关键约束

| 约束 | 说明 |
|---|---|
| image 用 `app-runtime-*` | 自带 PG/dbx/ttyd(ENTRYPOINT=start-app.sh) |
| dbx 4224 / ttyd 7681 | 固定端口,经 pingora path 访问 |
| PG 5432 | 容器内/集群内,**不对外**(Tcp 端口内网) |
| `POSTGRES_PASSWORD` | env 提供(PG 初始化);dbx 的 local-pg 走 socket 免密不受其影响 |
| PG 数据持久化 | 自动(PGDATA 在 workspace) |
| supervisor 管固定服务 | postgresql/dbx/ttyd/file-server-proxy + 用户服务;SIGTERM 优雅停 PG(INT 信号) |

## FAQ

**Q: 应用怎么连 PG?**
A: 容器内 `localhost:5432`(用 POSTGRES_* env)。如 node:`process.env.DATABASE_URL = postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@localhost:5432/${POSTGRES_DB}`。

**Q: dbx 怎么连 PG?**
A: 无需任何配置——dbx 启动时自动注入 local-pg 预置连接(unix socket 免密直连,面板免登)。浏览器打开即用。

**Q: 删容器数据会丢吗?**
A: 不会(purge=false)。PGDATA 在 workspace 持久化。同 app_id 重建挂回。`purge=true` 才清。

**Q: 不需要数据库的应用能用 app-runtime-* 吗?**
A: 能。容器仍起 PG/dbx/ttyd(资源占用),应用正常跑。

**Q: K8s 模式能用吗?**
A: 能,K8s 已是主链路(command 兼容 + per-app PVC)。本地用 Docker Compose 验证。

**Q: ttyd / dbx 支持外部子域名访问吗?**
A: 经 pingora path(`/api/v1/userapp/proxy/{tool}/prod/{user_id}/{app_id}/`)访问。外部系统可自行把子域名映射到这个 path(rcoder 不管子域名/DNS,见 [spec](../../specs/userapp-subdomain-access/userapp-subdomain-access-spec.md))。
