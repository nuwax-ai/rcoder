# 8. 带数据库的应用部署(PostgreSQL + pgweb + ttyd)

> UserApp 部署的应用,**容器内自带** PostgreSQL + pgweb(Web UI 操作数据库)+ ttyd(命令行终端),经 pingora path 路由访问,PG 数据持久化到 workspace(删容器不丢)。
>
> ✅ 实测环境(Docker Compose 模式):rcoder `@8090` API / `@8089` pingora。

## 概述

`app-runtime-*` 镜像(node/java/python/go/rust)单容器打包:

| 进程 | 端口 | 用途 | 对外 |
|---|---|---|---|
| 用户应用 | 用户端口(如 3000) | 用户 command | HTTP(pingora)|
| **pgweb** | 8081 | Web UI 操作 PostgreSQL | HTTP(pingora)|
| **ttyd** | 7681 | 命令行终端(/app 目录)| HTTP(pingora)|
| **PostgreSQL** | 5432 | 数据库(应用 + pgweb 访问)| 仅容器内/集群内(TCP)|

入口 `start-app.sh`(ENTRYPOINT):supervisor 管四进程;PG 初始化 + 数据落 `PGDATA=/app/data/pg`(workspace 持久化)。

---

## 部署流程

### Step 1:create(应用 + pgweb + ttyd + PG)

```bash
curl -X POST "$RCODER/api/v1/apps" -H 'Content-Type: application/json' -d '{
  "app_id": "app-myapp",
  "image": "app-runtime:latest",
  "command": ["sh","-c","cd /app/code && npm install && npm start"],
  "env": {
    "POSTGRES_USER": "app",
    "POSTGRES_PASSWORD": "secret123",
    "POSTGRES_DB": "myapp"
  },
  "ports": [
    {"name": "app",   "port": 3000, "expose_type": "http"},
    {"name": "pgweb", "port": 8081, "expose_type": "http"},
    {"name": "ttyd",  "port": 7681, "expose_type": "http"},
    {"name": "pg",    "port": 5432, "expose_type": "tcp"}
  ]
}'
```

- **image**:用 `app-runtime-{node,java,python,go,rust}:latest`(自带 PG/pgweb/ttyd,本地构建 `bash docker/app-runtime-base/build.sh <lang>`)
- **command**:用户应用启动(应用 HTTP 要 `--host 0.0.0.0`,见 [07](./07-前端项目部署.md))
- **env POSTGRES_***:PG 初始化(user/password/db,首启建库)
- **ports**:
  - 应用端口 + pgweb 8081 + ttyd 7681 → `Http`(经 pingora)
  - pg 5432 → `Tcp`(内网,不对外)

### Step 2:轮询就绪

```bash
curl "$RCODER/api/v1/apps/app-myapp" | jq '.data.status'
# Running(容器起);但 PG initdb 需数秒,pgweb/ttyd 随后 ready

# 确认四进程(容器内)
docker exec rcoder-app-app-myapp supervisorctl status
# app / pgweb / postgresql / ttyd 都 RUNNING
```

## 访问(经 pingora path 路由)

| 服务 | URL |
|---|---|
| 用户应用 | `http://{pingora}:8089/proxy/apps/u6/app-myapp/3000/` |
| **pgweb** | `http://{pingora}:8089/proxy/apps/u6/app-myapp/8081/` |
| **ttyd** | `http://{pingora}:8089/proxy/apps/u6/app-myapp/7681/` |

浏览器:
- **pgweb** → 打开后点 "Add Connection",填:
  `host=localhost port=5432 user=app password=secret123 database=myapp sslmode=disable`
  → 连上后建表/查改数据/跑 SQL
- **ttyd** → 直接进入命令行(`/app` 目录),可 `psql`、`node`、排查

## PG 连接

| 场景 | 连接串 |
|---|---|
| 应用(容器内) | `postgresql://app:secret123@localhost:5432/myapp` |
| 应用(K8s 集群内) | `postgresql://app:secret123@app-myapp-svc:5432/myapp` |
| pgweb UI | host=localhost port=5432(同凭证)|
| ttyd 命令行 | `psql -h localhost -U app -d myapp` |

## 数据持久化

PG 数据落 `PGDATA=/app/data/pg`(UserApp workspace 持久化目录):
- **Docker**:bind mount `app-workspace/{app_id}/` → `/app`,`/app/data/pg` 持久
- **K8s**:per-app PVC 挂 `/app`,`/app/data/pg` 持久
- **删容器(purge=false)**:PG 数据保留;同 `app_id` 重建自动挂回(误删找回)
- `purge=true` 才清空

> 验证:删容器 → PGDATA 文件留在卷 → 重建(同 app_id)→ `start-app.sh` 检测 PG_VERSION 跳过 initdb → 数据原样恢复。

## 关键约束

| 约束 | 说明 |
|---|---|
| image 用 `app-runtime-*` | 自带 PG/pgweb/ttyd(ENTRYPOINT=start-app.sh) |
| pgweb 8081 / ttyd 7681 | 固定端口,经 pingora path 访问 |
| PG 5432 | 容器内/集群内,**不对外**(Tcp 端口内网) |
| `POSTGRES_PASSWORD` | env 提供(PG 初始化) |
| PG 数据持久化 | 自动(PGDATA=/app/data/pg 在 workspace) |
| supervisor 管四进程 | app/pgweb/postgresql/ttyd;SIGTERM 优雅停 PG(INT 信号) |

## FAQ

**Q: 应用怎么连 PG?**
A: 容器内 `localhost:5432`(用 POSTGRES_* env)。如 node:`process.env.DATABASE_URL = postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@localhost:5432/${POSTGRES_DB}`。

**Q: pgweb 怎么连 PG?**
A: 浏览器开 pgweb → "Add Connection" 填 `localhost:5432` + POSTGRES_* 凭证(`sslmode=disable`)→ 连。容器内 pgweb 连 localhost PG。

**Q: 删容器数据会丢吗?**
A: 不会(purge=false)。PGDATA=/app/data/pg 在 workspace 持久化。同 app_id 重建挂回。`purge=true` 才清。

**Q: 不需要数据库的应用能用 app-runtime-* 吗?**
A: 能。容器仍起 PG/pgweb/ttyd(资源占用),应用正常跑。若想省资源,可用无 PG 的镜像(后续可提供 `ENABLE_POSTGRES=false` 开关关闭 PG/pgweb)。

**Q: K8s 模式能用吗?**
A: K8s 模式需 rcoder 改造(K8s command→args 兼容 ENTRYPOINT,见 spec §4.2)+ CephFS(per-app PVC)。本地用 Docker Compose 验证;K8s 待测试环境验证。

**Q: ttyd / pgweb 支持外部子域名访问吗?**
A: 经 pingora path(`/proxy/apps/{id}/{port}/`)访问。外部系统可自行把子域名映射到这个 path(rcoder 不管子域名/DNS,见 [spec](../../specs/userapp-subdomain-access/userapp-subdomain-access-spec.md))。
