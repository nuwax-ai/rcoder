# 12. 开发模式与文件接口（/api/userapp）

> 本篇覆盖 UserApp **开发阶段**：用户在沙箱（ComputerAgentRunner 容器）里初始化项目、
> 编辑文件、跑命令、起 dev server，直到交给 detect/confirm → build → publish 构建发布链。
> 接口宿主 = 沙箱容器内的 file-server（`http://{沙箱地址}:60000`），与 11 篇任务接口同进程。

## 1. 开发卷（核心概念）

UserApp 开发数据落在一块**独立共享卷**上，与用户沙箱日常数据隔离：

| 视角 | 路径 | 说明 |
|---|---|---|
| 沙箱容器内 | `/home/user/userapp-workspace/{app_id}/` | `USERAPP_WORKSPACE_DIR` 默认值 |
| builder 容器内 | `/app/userapp-workspace/{app_id}/` | helm builder 段 env 注入 |
| rcoder 容器内 | `/app/userapp-workspace/{app_id}/` | app 删除清理寻址（purge/destroy） |
| K8s | 共享 PVC `{ns}-rcoder-userapp-workspace`（ReadWriteMany，helm 预建） | 沙箱 Pod 与 builder STS 共挂 |
| Docker Compose | 宿主 `./userapp-workspace/`（bind mount） | |

要点：

- **一个沙箱可开发多个 app**：每个 app 一个 `{app_id}` 子目录，互不影响。
- **沙箱与 builder 共卷同构**：build 在 builder 容器执行时直接读同一份源码，构建产物
  `workspace-package-{release_id}.zip` 也落同目录，经 `GET /api/userapp/static/{appId}/{file}`
  下载流转——全链零文件搬运。
- **生命周期**：app 彻底删除（delete purge / storage destroy）时 rcoder 自动清理
  `{共享卷}/{app_id}/` 目录；共享卷本身永不删除。

## 2. 文件操作接口（15 个，computer 域同参镜像）

参数风格 camelCase；`appId` ≡ app_id（定位 `{开发卷}/{appId}`）；`userId` 保留但**不参与
路径**（仅审计）；`customTargetDir` 非空时**直接信任**作为目标根（由 Java 侧负责合法性，
与 computer 域同语义）。响应为裸 `{success, message, …}`（不包 HttpResult）。

### 文件读（GET，Query 传参）

| 接口 | 功能 | 参数 |
|---|---|---|
| `/api/userapp/get-file-list` | 文件树列表（轻量元信息；`recursive=false` 单层） | appId、userId、proxyPath、customTargetDir、relativePath、recursive |
| `/api/userapp/resolve-file` | 文件存在性解析 + 预览 URL | appId、userId、proxyPath、customTargetDir、filePath |
| `/api/userapp/search-files` | 无索引有界搜索 | appId、userId、proxyPath、customTargetDir、relativePath、kw、limit、maxVisit、timeoutMs（均必填正整数） |

### 文件写（POST）

| 接口 | 传参 | 说明 |
|---|---|---|
| `/api/userapp/files-update` | Json：appId、userId、customTargetDir、files[] | 批量 create/delete/rename/modify（modify 字节比较） |
| `/api/userapp/upload-file` | Multipart：appId、userId、filePath、customTargetDir、file | 单文件上传 |
| `/api/userapp/upload-files` | Multipart：appId、userId、customTargetDir、filePaths*、files* | 多文件（单文件失败不影响其余，响应逐文件结果） |
| `/api/userapp/generate-file` | Json：appId、userId、fileName、content、customTargetDir | 文本生成文件（fileName 可含相对子路径） |
| `/api/userapp/import-project` | Multipart：appId、userId、customTargetDir、file(zip) | 项目 zip 导入（白名单合并） |

### 下载（二进制 zip 响应）

| 接口 | 传参 | 说明 |
|---|---|---|
| `/api/userapp/zip-workspace` | Json：appId、userId、excludeDirs | 打包下载（保留 .gitignore 等 dot 文件） |
| `/api/userapp/download-all-files` | Query：appId、userId、customTargetDir | 全量下载（顶层前缀 `{userId}_{appId}/`；超 100MB 报错） |

### 执行与环境

| 接口 | 传参 | 说明 |
|---|---|---|
| `/api/userapp/execute-command` | Json：appId、userId、command | 终端命令（cwd=workspace，shell -c，超时=DEV_COMMAND_TIMEOUT_SECS） |
| `/api/userapp/get-logs` | Query：appId、userId、tailLines(默认200) | 最近执行日志（`.logs/` 下 mtime 最新文件末尾 N 行） |
| `/api/userapp/install-project` | Json：appId、userId、programmingLanguage | 依赖安装：typescript/ts→pnpm；python/py→pip |

### 初始化

| 接口 | 传参 | 说明 |
|---|---|---|
| `/api/userapp/init-project-template` | Multipart：appId、userId、file(zip)、enableGit | **开发起点**：模板 zip 解压到 `{开发卷}/{appId}/`（zip 内应含顶层项目目录）；enableGit=true 且 GIT_ENABLED 时自动 git init |
| `/api/userapp/push-skills-to-workspace` | Multipart：appId、userId、file(zip)、skillUrls(JSON数组)、agentId | 技能推到 `{ws}/.agents/skills`（agentId 仅日志——开发卷布局无 agent-store 软链语义） |

## 3. 与既有接口的衔接（全链同根）

```
init-project-template ──┐
upload / files-update ──┼→ {开发卷}/{appId}/ ──→ POST /api/userapp/projects/detect
execute-command / dev ──┘        （同根）           → POST /api/userapp/projects/confirm
                                                    → POST /api/userapp/build（制品落同目录）
                                                    → GET  /api/userapp/static/{appId}/{file}
                                                    → rcoder POST /api/v1/apps/{appId}/publish
```

- `detect` / `confirm` / `build` / `static`（存量接口）与 15 个文件接口**读同一棵开发卷**，
  任意容器（沙箱或 builder）调用结果一致（拓扑无关）。
- **开发服务生命周期（推荐走 UserApp 新契约，appId 唯一 key）**：

| 接口 | 传参 | 说明 |
|---|---|---|
| `POST /api/userapp/dev/start` | Json：appId、userId、basePath? | 启动开发服务（端口池分配 + pnpm install + 探活等待） |
| `POST /api/userapp/dev/stop` | Json：appId、userId | 停止（按 appId 定位进程组，无需 pid） |
| `POST /api/userapp/dev/restart` | Json：appId、userId、basePath? | 重启 |
| `POST /api/userapp/dev/build` | Json：appId、userId、basePath? | 开发编译（scripts.build；install+build+dist 拷贝；与顶层 `/api/userapp/build` 的发布打包语义不同） |
| `GET /api/userapp/dev/list` | — | 在跑的 UserApp 开发服务列表 |
| `GET /api/userapp/dev/logs` | Query：appId、startIndex?、logType?(main/temp) | 开发服务日志 |

  进程 key 内部用 `userapp:{appId}` 前缀与 web 项目的 projectId 空间隔离（appId≡project_id
  同值时两侧 workspace 在不同树，同 key 会互踩路径）；对外响应一律回 appId。
  旧 `/api/build/*` 接口（projectId 语义）仍服务 web agent 场景，UserApp 场景不必再传
  `projectId=appId` 双参数。

## 开发预览代理（与部署访问统一四段形态）

```
开发中:  {Pingora入口}/proxy/devapps/{user_id}/{app_id}/{port}/{path}   → 该用户沙箱同端口
部署后:  {Pingora入口}/proxy/apps/{user_id}/{app_id}/{port}/{path}      → app 运行容器
```

- **devapps 零注册零状态**：`dev/start` 响应里的 `port` + `user_id` + `app_id` 三元组直接拼
  URL 即可访问（Pingora 入口即 rcoder 的 8088 端口）；upstream 动态解析到用户沙箱容器。
- `app_id` 不参与解析（沙箱内端口已唯一），用于日志排障；`port` 不限范围——沙箱自装
  pingap/app-cli 的场景代理 9080 一个端口即整应用统一入口（拓扑=生产）。
- 多 app 并行：同沙箱 app-a（4000）/app-b（4001）各拼各的 URL，互不干扰。
- 部署后 `access.external.http` 返回的就是四段 path（`POST /api/v1/apps` 的 `user_id`
  落 `userapp_metadata`，URL 由其拼出）——**开发切部署前端只改 `devapps`→`apps` 一段**。
- 局限：沙箱容器重建后 IP 变化有短窗口旧值（下次 ensure 修正）；user 无沙箱 → 502。
- 模板 zip 的顶层目录即子项目目录名（如 `my-app/package.json`）——`detect` 的
  `projectDir` 传该目录名，与 workspace 多项目模型一致。

## 4. Java 对接指引（从 computer 域迁移）

这 15 个接口是 computer 域（ComputerFileClient/WorkspaceRpcClient 调用面）的镜像，
迁移只需两步：

1. URL 前缀 `/api/computer/*` → `/api/userapp/*`；
2. 参数 `cId` → `appId`（其余字段名、multipart 字段名、响应结构完全同构；
   `files-update`/`import-project` 响应中的 `cId` 回显键同步变为 `appId`）。

不迁移的 computer 接口：`create-workspace(-v2)`/`delete-workspace`（workspace 生命周期
归 rcoder 容器编排）、`build-agent-package`/`cleanup-build-artifacts`（nuwax agent 包链路）。

## 5. 部署注意

- K8s：升级 helm 前**删除存量 builder STS**（volume 模板从 per-app PVC 变更为共享卷，
  STS 不会自动滚动）；存量沙箱 Pod 无新挂载（Pod 不热更），重建后生效。
- Docker Compose：`docker/userapp-workspace/` 宿主目录由 starter 自动创建，已在
  `.gitignore` 忽略。
- 共享卷容量默认 1Ti（values `sharedVolumes.rcoderUserappWorkspace.size`），含开发源码
  与构建制品 zip（app 删除时统一清理）。
