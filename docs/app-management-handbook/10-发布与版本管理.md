# 10. 发布与版本管理

> UserApp 构建发布全流程：从源码构建镜像 → 上传制品 → 激活发布 → 版本回滚。这是**新增的发布体系**，与直接 create 部署并存。

---

## 发布体系概览

```
┌─────────────────────────────────────────────────────────────────┐
│  发布全流程（Java 业务侧视角）—— 三阶段                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 构建阶段                                                     │
│     POST /apps/{id}/build                                        │
│     └→ RCoder 在 builder 容器内编译源码 → 产出制品 zip           │
│         （异步：返回 task_id，轮询 GET /apps/publish/tasks/{id}）│
│                                                                 │
│  2. 预备阶段                                                     │
│     POST /apps/{id}/releases/prepare                             │
│     └→ RCoder 从 URL 下载制品包 + sha256 校验 → 入库（不切流）   │
│         （同步：校验通过即返回 ReleaseInfo）                      │
│                                                                 │
│  3. 激活阶段（单接口收敛）                                        │
│     POST /apps/{id}/releases/{rid}/activate                      │
│     └→ 切流 → ensure 运行容器 → 等就绪（readinessTimeoutSeconds）│
│         ├→ 就绪   → active（清快照、retention）                  │
│         └→ 未就绪 → failed（**保留现场**，200 + status=failed）  │
│                                                                 │
│  4.（失败后可选）显式回滚                                         │
│     POST /apps/{id}/releases/rollback                            │
│     └→ `.rollback` 快照恢复上一 active（秒级）                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

> **设计原则：失败保留现场，恢复动作显式化**。激活失败不自动回滚——自动回滚会销毁排查
> 线索（code 被覆盖、制品包被删）。失败后 code=失败版（应用保持 Error/启动失败状态，
> 日志/events/ttyd 可查）、`.rollback`=上一版快照、制品包均**原样保留**；确认放弃
> 新版后再调 rollback 一键恢复。

---

## 发布状态机

```
prepared ──activate(切流+ensure容器+等就绪)──→ active   （就绪：清 .rollback、旧 active→prepared、retention）
    └──就绪失败/启动失败──→ failed  （现场保留：code=失败版、.rollback=上一版、制品包保留）
failed ──rollback(快照恢复)──→ 恢复上一 active（失败版保持 failed 供追溯）
任意时点 ──activate(旧 prepared release_id)──→ 手动回退/重部署（分钟级，制品在 retention 内）

幂等/边界规则：
- 重复 activate 已 active 的 release → 直接返回（幂等）
- activate 就绪失败 → 200 + status=failed（发布结果，非系统错误；不要按 5xx 重试）
- rollback 无快照（最近一次部署成功）→ 幂等返回当前 active
- rollback 首次发布失败（无旧版本）→ 409 ERR_INVALID_STATE
- retention 永不自动删 active/failed（failed 可手动 delete）
```

## 构建接口

### POST `/apps/{app_id}/build` — 触发源码构建

在 UserApp Builder 容器内编译源码，产出可部署制品 zip。

**Builder 自动创建**：任务开始时若 Builder 容器未注册（不存在、或 rcoder 重启后内存注册丢失），先自动创建并注册（SSE `stage=EnsureBuilder`，K8s 拉镜像可能数十秒），再进入 `stage=Build`。**无需（也不再提供）单独的 ensure-builder 调用**；Builder 创建失败以任务 `failed` 终态呈现。

**请求体** `BuildBody`：
```jsonc
{
  "projectId": "app-order-svc"  // 源码所在 project（与 app_id 关联的构建项目）
}
```

**响应** `HttpResult<PublishTaskData>`：
```jsonc
{
  "success": true,
  "data": {
    "task": {
      "id": "019123456789abcdef",
      "appId": "app-order-svc",
      "kind": "build",
      "status": "running",
      "stage": "preparing",
      "createdAt": "2026-08-15T10:00:00Z"
    }
  }
}
```

**错误**：
| HTTP | code | 说明 |
|---|---|---|
| 400 | ERR_VALIDATION | 参数错误（app_id/project_id 不合法） |
| 409 | ERR_CONFLICT | 同 app 已有活跃构建/发布任务 |
| 429 | ERR_TOO_MANY_REQUESTS | 全局任务容量上限 |
| 500 | ERR_INTERNAL_SERVER_ERROR | 内部错误 |

> Builder 创建/agent-runner 不可达不再以 HTTP 404 返回——任务创建总是 200，Builder 自动创建失败会体现在任务终态（`failed`，error 含原因），经任务查询/SSE 获取。

**轮询任务状态**：
```bash
# 轮询直到 status 为终态（completed/failed/cancelled）
curl $RCODER/api/v1/apps/publish/tasks/019123456789abcdef

# SSE 实时进度（推荐，带 from_seq 断点续传）
curl -N "$RCODER/api/v1/apps/publish/tasks/019123456789abcdef/stream?from_seq=0"
```

---

### POST `/apps/{app_id}/publish` — 触发完整发布流程

build + prepare + activate + 等待确认，一步到位。适合简单场景（不需要在 build 和 activate 之间做人工检查）。

**请求体** `PublishBody`：同 build。

**响应** `HttpResult<PublishTaskData>`：返回发布任务，`kind=publish`。

## 发布版本接口

### POST `/apps/{app_id}/releases/prepare` — 预备发布

从指定 URL 下载制品包，校验 sha256 后入库。**不切流**——应用仍运行当前版本。

**请求体** `PrepareReleaseRequest`：
```jsonc
{
  "releaseId": "rel-20260815-001",           // 调用方生成的发布 ID（幂等键）
  "url": "https://ci.example.com/build/app-v1.2.0.zip",
  "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "sizeBytes": 10485760,                      // 制品字节数
  "retention": 5                               // 可选：保留份数（默认取全局策略）
}
```

**响应** `ReleaseInfo`（注意：此接口返回裸对象，不包 HttpResult）：
```jsonc
{
  "releaseId": "rel-20260815-001",
  "sha256": "e3b0c44298fc...",
  "sizeBytes": 10485760,
  "status": "prepared",
  "createdAt": "2026-08-15T10:30:00Z"
}
```

**幂等**：同 release_id + 同 sha256 + 同 size 重复 prepare → 直接返回已有记录。

**错误**：
| HTTP | code | 说明 |
|---|---|---|
| 400 | ERR_VALIDATION | 参数校验失败（sha256 格式、retention 越界、URL 非法） |
| 404 | ERR_APP_NOT_FOUND | 应用不存在 |
| 409 | ERR_CONFLICT | release_id 已存在但摘要/大小不一致 |
| 500 | ERR_BACKEND_ERROR | 下载失败/校验失败/存储 IO 错误 |

---

### POST `/apps/{app_id}/releases/{release_id}/activate` — 激活发布（单接口）

**切流 → ensure 运行容器 → 等就绪 → 提交/失败**，一次调用收敛到终态（首次发布时运行容器
不存在会自动创建，image=app-runtime）。就绪判定 = status Running 且 health 非 Unhealthy。

**请求体** `ActivateReleaseRequest`：
```jsonc
{
  "readinessTimeoutSeconds": 300  // 可选：默认 300，范围 5..=1800（越界 400）。
                                   // Java 等慢启动应用可调大；上限与 build 超时对齐。
}
```

> ⚠️ **等待期间本请求同步阻塞**：调用方 HTTP client 读超时须 ≥ readinessTimeoutSeconds + 余量。
> Java 超时断连后发布仍会收敛到终态，可事后查 `GET /releases`。

**响应** `ReleaseInfo`：
- 就绪 → `status=active`（清 `.rollback` 快照、旧 active 让位 prepared、retention 清理）。
- 就绪超时/进入 Error → **`200` + `status=failed`**（发布结果而非系统错误——**不要按 5xx
  重试**；现场已保留，按 `data.status` 分支处理）。`failureMessage` 携带原因。

**失败现场三不动**（供排查）：`code`=失败版（应用保持 Error，日志/events/ttyd 可查）、
`.rollback`=上一版快照、失败制品包。排查后放弃新版 → `rollback` 接口一键恢复。

**错误**：
| HTTP | code | 说明 |
|---|---|---|
| 400 | ERR_VALIDATION | 参数校验失败（含 readinessTimeoutSeconds 越界） |
| 404 | ERR_APP_NOT_FOUND / release 不存在 / 制品包文件缺失 | — |
| 500 | ERR_BACKEND_ERROR | 切流/拉起/索引写入失败（操作错误，非就绪失败） |

**幂等**：重复 activate 已 active 的 release → 直接返回。

**崩溃恢复**：激活中途进程中断时 index 停留在激活前状态（code 可能已切新版）——用
`rollback`（快照在）或重新 activate 同一 release 收敛。

---

### POST `/apps/{app_id}/releases/rollback` — 回滚到最近一次成功版本

`.rollback` 快照 rename 恢复上一 active，**秒级**（不需要重新解包部署）。

**请求体** `RollbackReleaseRequest`：
```jsonc
{
  "message": "排查后放弃 v1.2.0，回退"  // 可选，记入失败版 failure_message 供追溯
}
```

**响应** `ReleaseInfo`（恢复后的 active 版本）。

**行为**：
| 场景 | 结果 |
|---|---|
| 有 `.rollback` 快照（最近一次 activate 失败、现场还在） | stop → 清失败版 code → 快照恢复 → start；失败版保持 failed（message 记入） |
| 无快照（最近一次部署是成功的） | 幂等返回当前 active（无事可做） |
| 首次发布失败（无旧版本可回滚） | `409 ERR_INVALID_STATE` |

**与 activate 旧版本的分工**：
- `rollback` = 快照恢复，秒级 → 覆盖"最近一次失败想放弃新版"；
- `activate 旧 prepared release_id` = 重新解包部署，分钟级 → 覆盖"成功运行一段时间后想回退"
  （此时 `.rollback` 已被提交清理，制品在 retention 内）。

---

### GET `/apps/{app_id}/releases` — 列出发布版本

**响应** `ReleaseListResponse`：
```jsonc
{
  "activeReleaseId": "rel-20260815-001",
  "lastFailedReleaseId": null,      // 最近一次激活失败（非 null → 可 rollback 恢复）
  "retention": 5,
  "releases": [
    { "releaseId": "rel-20260815-001", "status": "active", ... },
    { "releaseId": "rel-20260810-002", "status": "prepared", ... }
  ]
}
```

---

### POST `/apps/{app_id}/releases/{release_id}/delete` — 删除发布记录

删除非 active 的 release（保留策略外的手工清理）。

**错误**：active 状态不可删（409）。

## 完整发布流程 curl 示例

```bash
# 假设应用已创建（见 02-接口手册 POST /apps）
APP_ID=app-order-svc
RCODER=http://127.0.0.1:8090

# ── 方式 A：完整发布（一步到位）──
# 1. 触发发布（build → prepare → activate 一条链；activate 内含等就绪）
TASK_ID=$(curl -s -X POST $RCODER/api/v1/apps/$APP_ID/publish \
  -H 'Content-Type: application/json' \
  -d "{\"projectId\":\"$APP_ID\"}" | jq -r '.data.task.id')

# 2. SSE 监听进度（EnsureBuilder → Build → Prepare → Activate → 终态）
curl -N "$RCODER/api/v1/apps/publish/tasks/$TASK_ID/stream?from_seq=0"

# ── 方式 B：分步发布（build 和 activate 之间做人工检查）──
# 1. 构建
curl -X POST $RCODER/api/v1/apps/$APP_ID/build \
  -H 'Content-Type: application/json' \
  -d "{\"projectId\":\"$APP_ID\"}"
# → 轮询任务完成，拿到制品 URL

# 2. 预备
curl -X POST $RCODER/api/v1/apps/$APP_ID/releases/prepare \
  -H 'Content-Type: application/json' \
  -d '{"releaseId":"rel-001","url":"https://ci/app.zip","sha256":"...","sizeBytes":10485760}'

# 3. 激活（单接口：等就绪收敛到 active/failed；Java 大应用调大超时）
curl -X POST $RCODER/api/v1/apps/$APP_ID/releases/rel-001/activate \
  -H 'Content-Type: application/json' \
  -d '{"readinessTimeoutSeconds":600}'
# → status=active 发布成功；status=failed 现场保留（failureMessage 含原因）
```

## 回滚

```bash
# 场景 1：最近一次 activate 失败（现场保留）→ 快照恢复，秒级
curl -X POST $RCODER/api/v1/apps/$APP_ID/releases/rollback \
  -H 'Content-Type: application/json' \
  -d '{"message":"排查后放弃 v1.2.0，回退"}'

# 场景 2：成功运行一段时间后想回退 → activate 旧版本，分钟级
PREV_REL=$(curl -s $RCODER/api/v1/apps/$APP_ID/releases | jq -r '.releases[] | select(.status=="prepared") | .release_id' | head -1)
curl -X POST $RCODER/api/v1/apps/$APP_ID/releases/$PREV_REL/activate
# → 同样等就绪收敛到 active/failed
```
