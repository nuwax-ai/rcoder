# 10. 发布与版本管理

> UserApp 构建发布全流程：源码构建 → 取包入 Java 制品库 → `start {url}` 部署。
> **`start {url}` 是唯一部署入口**（制品下载/解压/换 code 由运行容器内 app-cli 完成，
> 生产卷为 RBD，rcoder 不挂载卷）。

---

## 发布体系概览

```
┌─────────────────────────────────────────────────────────────────┐
│  发布全流程（Java 业务侧视角）—— Java 六步编排（终态）             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. POST /api/v1/userapp/workspace {app_id,user_id}    —— 首次注册   │
│  2. POST /apps/{id}/build {project_id=app_id}     —— 云端构建   │
│     └→ builder 容器内编译 → 制品 zip（异步 task）                │
│  3. GET /publish/tasks/{task_id}（轮询或 SSE）    —— 终态+摘要   │
│     （快照含 file_name / sha256 / size_bytes）                  │
│  4. GET /api/v1/userapp/static/{app_id}/{file_name}  —— 取包       │
│     （须带 X-App-Id header；支持 Range）                        │
│  5. Java 上传到自己的制品库 → 得到部署 url                       │
│     （⚠️ 不可回指 rcoder static——转发层强制 X-App-Id，           │
│      rcoder Downloader 不带该 header 会 400）                   │
│  6. POST /apps/{id}/start {url, release_id, sha256, ...}         │
│     └→ rcoder 注入部署 env → 运行容器 Recreate 换 Pod →          │
│        app-cli 启动段容器内下载/校验/解压/换 code → 等就绪 →      │
│        包内 database SQL 自动执行                                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

> **设计原则：失败保留现场，恢复动作显式化**。部署失败（下载/校验/启动失败）不自动
> 回滚——code/ 现场不破坏（换 code 只做同卷 rename），容器日志/events/ttyd 可查；
> 放弃新版后用**旧制品 URL 重新 start** 恢复。

---

## 部署模型（RBD 卷·容器中心化）

- **生产运行卷**：per-app RWO RBD PVC（rcoder 零挂载）。制品下载、解压、code 目录
  切换全部在**运行容器内**由 app-cli 启动段完成。
- **幂等**：同一 `release_id` 重复 start / Pod 重启 → 卷上 `.deploy-state.toml`
  marker 命中，**不重下载**（换 env 才触发换 Pod 重新部署）。
- **上一代保留**：换 code 时旧版挪到卷上 `/app/.previous`（仅一代），供紧急人工
  恢复；日常回滚走"旧制品 URL 重新 start"。
- **readiness 窗口**：下载+解压+起服务都在就绪窗口内（默认 300s，大制品可让 Java
  传大 `sha256` 校验 + 稍长超时预算）。下载期间 app-cli 的 liveness 由部署段
  托管应答（`/health` 200），不会被 kubelet 误杀。

## 发布/部署接口

### POST `/apps/{app_id}/start` — 部署 + 启动（唯一部署入口）

**请求体** `StartAppRequest`（全可选；带 `url` 即部署语义）：
```jsonc
{
  "url": "https://artifact.example.com/app-v1.2.0.zip",  // 制品包地址（Java 制品库）
  "release_id": "rel-20260815-001",   // 部署标识（幂等 marker；缺省自动生成
                                      //  rel-{12hex}-{8hex}；重试传同值避免重下载）
  "sha256": "e3b0c44298fc...",        // 可选校验（64 hex；空 = 信任内网源跳过校验）
  "env": {"KEY": "value"},            // 可选：env 整段替换（与 update 同语义）
  "idle_timeout_seconds": 0,          // 可选：0 = 常驻（不闲置回收）
  "pg": {"username": "u", "password": "p"},  // 可选：部署后 PG 凭据对齐（失败不阻断）
  "auto_execute_sql": true,           // 缺省 true：执行包内 database SQL
  "user_id": "user-123"               // 可选：owner 兜底注册
}
```

**行为**（rcoder 侧）：
1. `release_id` 生成/校验（`[A-Za-z0-9._-]+`，无前导点——进容器 env 与 fs 路径）；
2. PVC ensure（K8s）；
3. env 组装（业务 env 或 live 回退 + 部署三元组 `APP_DEPLOY_URL/APP_RELEASE_ID/
   APP_DEPLOY_SHA256` 权威覆盖）→ 已存在 app 走 update 通道（SSA + config-hash
   → **Recreate** 换 Pod），不存在则创建（镜像/端口/探针平台内定）；
4. `wait_app_ready`（默认 300s：容器内 app-cli 部署段完成下载/解压/起服务）；
5. 包内 `database/*.sql` 自动执行（容器内 `find` 列举 + `psql -f`，根目录先于子项目、
   文件名升序；单文件失败仅收集进 `sql_report` 不阻断）。

**响应** `StartAppResult`：`runtime` + `release_id` + `pg_aligned/pg_error` + `sql_report`。

**错误**：
| HTTP | code | 说明 |
|---|---|---|
| 400 | ERR_VALIDATION | 参数错误（release_id 非法、sha256 非 64 hex、env 带保留键） |
| 404 | ERR_APP_NOT_FOUND | 应用不存在（无 url 传统启动路径） |
| 409 | ERR_CONFLICT | 有进行中的 update/delete 并发 |
| 500 | ERR_BACKEND_ERROR | readiness 超时（含容器内下载失败 supervisord 重试耗尽）/ SSA 失败 |

> ⚠️ **等待期间本请求同步阻塞**：Java HTTP client 读超时须 ≥ 300s + 下载时长余量。
> 超时断连后部署仍在容器内收敛（supervisord 重试），可事后 `GET /apps/{id}` 查状态。

## 回滚

**回滚 = 用旧制品 URL 重新 `start`**（制品库在 Java 侧，零新接口）：

```bash
# 用上一个版本的制品 url 重新部署（release_id 用旧值或新生成均可）
curl -X POST $RCODER/api/v1/userapp/$APP_ID/start \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://artifact.example.com/app-v1.1.0.zip","release_id":"rel-v1.1.0","sha256":"..."}'
```

紧急人工恢复（不可重新部署时）：运行容器卷上 `/app/.previous` 保留上一代 code
（仅一代），可 exec 进容器手工交换——平台不提供 API（避免与 Java 制品库双事实源）。

## 构建接口

### POST `/apps/{app_id}/build` — 触发源码构建

在 UserApp Builder 开发容器内编译源码，产出可部署制品 zip。

**Builder 自动创建**：任务开始时若 Builder 容器未注册（不存在、或 rcoder 重启后内存注册丢失），先自动创建并注册（SSE `stage=EnsureBuilder`，K8s 拉镜像可能数十秒），再进入 `stage=Build`。**无需（也不再提供）单独的 ensure-builder 调用**；Builder 创建失败以任务 `failed` 终态呈现。

**请求体** `BuildBody`：
```jsonc
{
  "project_id": "app-order-svc"  // 源码所在 project（与 app_id 关联的构建项目）
}
```

**响应** `HttpResult<PublishTaskData>`：
```jsonc
{
  "success": true,
  "data": {
    "task": {
      "id": "019123456789abcdef",
      "app_id": "app-order-svc",
      "kind": "build",
      "status": "running",
      "stage": "preparing",
      "created_at": "2026-08-15T10:00:00Z"
    }
  }
}
```

**错误**：
| HTTP | code | 说明 |
|---|---|---|
| 400 | ERR_VALIDATION | 参数错误（app_id/project_id 不合法） |
| 409 | ERR_CONFLICT | 同 app 已有活跃构建/发布任务 |
| 429 | ERR_TOO_MANY_REQUESTS | 全局任务容量上限 |
| 500 | ERR_INTERNAL_SERVER_ERROR | 内部错误 |

> Builder 创建/agent-runner 不可达不再以 HTTP 404 返回——任务创建总是 200，Builder 自动创建失败会体现在任务终态（`failed`，error 含原因），经任务查询/SSE 获取。

**轮询任务状态**：
```bash
# 轮询直到 status 为终态（completed/failed/cancelled）
curl $RCODER/api/v1/userapp/publish/tasks/019123456789abcdef

# SSE 实时进度（推荐，带 from_seq 断点续传）
curl -N "$RCODER/api/v1/userapp/publish/tasks/019123456789abcdef/stream?from_seq=0"
```

**Electron（nuwaClaw）本地开发链**：import-project 上传 workspace zip → 云端 build
（本地产不出合法 release.lock——依赖 builder 镜像 env）→ 取包 → 上传云端 → start+url。

## 完整发布流程 curl 示例

```bash
APP_ID=app-order-svc
RCODER=http://127.0.0.1:8090

# 1. 构建（异步 task）
TASK_ID=$(curl -s -X POST $RCODER/api/v1/userapp/$APP_ID/build \
  -H 'Content-Type: application/json' \
  -d "{\"projectId\":\"$APP_ID\"}" | jq -r '.data.task.id')

# 2. 轮询终态（快照含 artifact 摘要 file_name/sha256/size_bytes）
curl -s $RCODER/api/v1/userapp/publish/tasks/$TASK_ID | jq '.data.task'

# 3. 取包（带 X-App-Id）→ 上传 Java 制品库 → 得 url
curl -s -H "X-App-Id: $APP_ID" \
  "$RCODER/api/v1/userapp/static/$APP_ID/app-package.zip" -o /tmp/app.zip

# 4. 部署（唯一入口；readiness 窗口内完成容器内下载+解压+起服务）
curl -X POST $RCODER/api/v1/userapp/$APP_ID/start \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://artifact.example.com/app.zip","release_id":"rel-001","sha256":"<64hex>"}'
```
