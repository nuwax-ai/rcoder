# 7. 前端项目部署（React / Vue + Vite）

> 本文以 **vite 前端项目**（`react-vite-template` / `vue3-vite-template`）为例，演示 UserApp 从模板到「通过 Pingora 反代访问」的完整流程。
> 通用发布/访问流程见 [06-快速开始-发布与访问](./06-快速开始-发布与访问.md)；本文聚焦**前端与通用流程的差异点**。
>
> ✅ **实测环境**（2026-07）：Docker Compose 模式，rcoder `@8090`、Pingora 宿主机 `8089`→容器 `8088`。
> K8s 模式 REST 契约一致，放测试环境验证（见末尾「Docker vs K8s」）。

## 概述

两条主线：

1. **应用发布**：upload 模板 zip → create（node 镜像 + install + vite）→ 轮询就绪
2. **应用访问**：GET 拿 access path → 拼 Pingora 入口 → 访问

> ⚠️ **前端 vs 通用流程的 3 个关键差异**（照 06 通用流程部署前端会踩的坑）：
>
> | 差异点 | 通用流程（06） | 前端项目（本文） |
> |---|---|---|
> | 镜像 | `app-runtime-java` 等（阿里云 registry） | `app-runtime-node`（生产运行时镜像，本地构建见 Step 0） |
> | 启动命令 | `java -jar ...` | `npm install && npx vite --host 0.0.0.0`（**必须 `--host`**） |
> | 端口 | 业务端口（8080） | vite 默认 `5173`（dev）/ `4173`（preview） |

## 主线一：应用发布

### Step 0：前置（Docker Compose 模式）

```bash
export RCODER=http://127.0.0.1:8090      # rcoder API（Docker Compose 主服务）
export PINGORA=http://127.0.0.1:8089     # Pingora 入口（宿主机 8089 → 容器 8088）
```

- **镜像**：`app-runtime-node:latest`（生产运行时：Node 24 + 排查工具 + ttyd，1.02GB）。
  本地构建：`bash docker/app-runtime-base/build.sh node`（自动先 base 后 node → `app-runtime-node:latest`）。
  也可退而用 `node:20-alpine`（49MB，无排查工具/ttyd）。
  > 镜像自带 `HEALTHCHECK` 查 `localhost:8080/health`，但 rcoder Docker 模式只看容器 `running`（`docker_runtime.rs` phase 映射不看 `Health`），**不受影响** —— vite 在 5173 不匹配也仍是 `Running`。
- **app_id**：外部指定（如 `app-react-vite`），便于「先 upload 再 create」。

> 💡 **为什么先 upload 再 create**：前端启动依赖 `code/` 里的源码。指定 app_id 后，`upload` 会自动建目录（`create_dir_all`），所以能**先把源码解压进去**，再 create —— 容器一启动就有源码，不会因空目录 CrashLoop。

### Step 1：上传模板 zip → code/

```bash
APP_ID=app-react-vite

# upload：魔数识别 zip → 自动解压到 target 目录（code/），保留目录结构
curl -X POST "$RCODER/api/v1/apps/$APP_ID/upload" \
  -F "file=@./react-vite-template.zip" \
  -F "target=code/"
# → { "file_path": "code/", "extracted_count": 62, ... }
```

- **target=code/**：解压目录（末尾 `/`）。zip 解压后 `code/package.json`、`code/src/`、`code/index.html` 等平铺。
- Vue 模板同理：换 zip 即可（`vue3-vite-template.zip`）。

### Step 2：创建应用（关键：vite --host）

```bash
curl -X POST "$RCODER/api/v1/apps" -H 'Content-Type: application/json' -d '{
  "app_id": "app-react-vite",
  "name": "react-vite-template",
  "image": "node:20-alpine",
  "command": ["sh", "-c",
    "cd /app/code && npm install --no-audit --no-fund && npx vite --host 0.0.0.0 --port 5173"],
  "ports": [{"name": "http", "port": 5173, "expose_type": "Http"}],
  "resources": {"cpu": "1", "memory": "512Mi"}
}' | jq '.data.status, .data.access'
# → "Running"
# → { "external": { "http": "/proxy/apps/app-react-vite/5173", ... } }
```

**关键点**：

- **`--host 0.0.0.0`**：vite 默认只监听 `localhost`，容器内 Pingora 转发不进来 —— **必须加**，否则访问 502。
- **`sh -c "... && ..."`**：一个 command 串联 `npm install`（一次性）和 `vite`（长驻）。install 完成后 vite 才启动。
- **`--no-audit --no-fund`**：减少 install 噪声输出。
- **端口 5173** = vite dev 默认端口；`ports[].expose_type = "Http"`（走 Pingora）。

### Step 3：轮询就绪（install + vite ready）

`create` 立即返回 `Running`（容器在跑），但 vite 要等 `npm install` 完成（react 模板 458 包，约 1 分钟）。

```bash
# 看容器日志：install 进度 → vite ready
docker logs rcoder-app-$APP_ID 2>&1 | tail -15
# 期望看到：
#   added 458 packages in 1m
#     VITE v5.4.21  ready in 194 ms
#     ➜  Network: http://192.168.97.7:5173/

# 或查运行时状态（conditions: Ready=True）
curl -s "$RCODER/api/v1/apps/$APP_ID" | jq '.data.status, .data.conditions'
```

> `status=Running` 只代表容器在跑，**不代表 vite 已监听**。判断 vite 就绪看日志的 `VITE ready`，或直接 Step 4 访问（502 = 还没好，200 = 就绪）。

### Step 4：更新 / 停止 / 重启 / 删除（通用，同 06）

```bash
# 改了源码后重新 upload + 重启（让 vite 重新加载；vite HMR 通常自动热更，无需重启）
curl -X POST "$RCODER/api/v1/apps/$APP_ID/upload" -F "file=@./new-code.zip" -F "target=code/"
curl -X POST "$RCODER/api/v1/apps/$APP_ID/restart"

# 停止（scale=0，保留数据）/ 启动 / 删除（默认保留数据）
curl -X POST "$RCODER/api/v1/apps/$APP_ID/stop"
curl -X POST "$RCODER/api/v1/apps/$APP_ID/start"
curl -X POST "$RCODER/api/v1/apps/$APP_ID/delete"
```

## 主线二：应用访问（Pingora 反代）

### Step 1：拿访问地址

```bash
curl -s "$RCODER/api/v1/apps/$APP_ID" | jq '.data.access'
# {
#   "external": { "http": "/proxy/apps/app-react-vite/5173", "tcp": [] },
#   "internal": { "domain": "rcoder-app-app-react-vite", "ports": [{"name":"http-5173","port":5173}] }
# }
```

- `access.external.http` = **path**（不含 host）。拼上 Pingora 入口即是完整 URL。

### Step 2：访问应用

```bash
# 完整 URL = {Pingora 入口} + {access.external.http} + {应用内路径}
curl "$PINGORA/proxy/apps/app-react-vite/5173/"
# → <!doctype html><html>... <title>React Vite App</title> ...
#   <script type="module" src="/@vite/client"></script>   ← vite 注入的 HMR client
#   <div id="root"></div>
#   <script type="module" src="/src/main.tsx"></script>

# 浏览器直接打开（推荐，能看完整页面 + HMR）：
#   http://127.0.0.1:8089/proxy/apps/app-react-vite/5173/
```

### Step 3：Pingora 路由原理

```
浏览器 → 127.0.0.1:8089（宿主机）
        → rcoder 容器 :8088（Pingora 监听）
        → 按 path /proxy/apps/{app_id}/{port}/ 解析 (app_id, port)
        → 查 app_backends 注册表（create 时注册：backend = container_ip:5173）
        → 转发到 app-react-vite 容器 192.168.97.7:5173（vite dev server）
        → 返回 index.html（vite 注入 @vite/client + @react-refresh）
```

- **按 (app_id, port) 路由**：多个 app 同端口（5173）不冲突，靠 app_id 区分。
- **未注册 → 502**（app 不存在 / 端口不对 / vite 还没 ready）。
- **HMR**：vite dev 注入 `/@vite/client`，改源码自动热更新（经 Pingora 的 ws 透传）。

## FAQ

**Q: 为什么 vite 一定要 `--host 0.0.0.0`？**
A: vite 默认只监听 `127.0.0.1`（容器内 loopback）。Pingora 从 rcoder 容器转发到 app 容器的 eth0 IP，不走 loopback，所以默认配置下访问 502。`--host 0.0.0.0` 让 vite 监听所有网卡，Pingora 才能转达。

**Q: `app-runtime-node` 镜像地址怎么选？**
A: **两个测试命名空间对应两个后端**，地址不能混用：
- **K8s 模式** → `nuwax-k8s-test/app-runtime-node:<ver>-{arm64|amd64}`（06 文档场景）
- **Docker Compose 模式** → `nuwax-test/app-runtime-node:<ver>-{arm64|amd64}`（本地 `docker images` 可见）

两者都**无 `latest` tag**（只有 `0.1.x-arm64/amd64`）。在 Docker Compose 模式下传 `nuwax-k8s-test/...` 会拉不到（命名空间不匹配该后端，就是之前 `not found` 的原因）。**最省事：本地构建** `bash docker/app-runtime-base/build.sh node` → `app-runtime-node:latest`（**两端通用**，本文用此，≈ 生产最新版）。

**Q: 用 dev 模式还是 preview / build 模式？**
A:
- **dev 模式**（本文，`vite --host`）：开发联调用，带 HMR，启动快（install 后秒起），但产物未优化、不适合压测。
- **preview 模式**（`vite build && vite preview --host`）：先构建再预览，产物 = 生产包，贴近线上表现。
- **生产托管**（`vite build` → 静态服务器如 nginx 托管 `dist/`）：正式上线用，需 nginx 镜像。

| 模式 | command | 适用 |
|---|---|---|
| dev | `npm install && npx vite --host 0.0.0.0 --port 5173` | 开发联调、HMR |
| preview | `npm install && npm run build && npx vite preview --host 0.0.0.0 --port 4173` | 验证生产构建 |
| 静态托管 | `npm install && npm run build && <nginx/serve dist/>` | 正式上线 |

**Q: HMR（热更新）经 Pingora 能工作吗？**
A: 页面访问已实测通过（HTTP 200）。vite dev 注入 `/@vite/client` 建立 WebSocket 做热更新，经 Pingora 反代时需 Pingora 透传 WebSocket upgrade + vite-hmr 子协议。若页面能开但改代码不热更，检查 Pingora 的 ws 透传配置，或退而用 `restart` 手动重载。

**Q: npm install 很慢怎么办？**
A: react 模板依赖多（radix-ui 全家桶等），首次 install 约 1 分钟。优化：
- 换国内 npm mirror：command 里加 `--registry=https://registry.npmmirror.com`
- 用 pnpm（更快 + 缓存友好）：镜像里有 pnpm 时 `pnpm install`，否则 `corepack enable && pnpm install`
- 预构建镜像（把 `node_modules` 烤进镜像），command 只跑 `vite --host`

**Q: 用 pnpm 还是 npm？**
A: 模板 `package.json` 的 `scripts` 里 `dev`/`build` 直接调 `vite`/`tsc`（不依赖 pnpm），所以 `npm install` + `npm run dev`（或直接 `npx vite`）就能跑。模板带 `pnpm-workspace.yaml`，若镜像有 pnpm 用 pnpm 更快；没有就用 npm，不影响功能。

**Q: Vue3 模板有什么不同？**
A: 几乎没区别。换 zip（`vue3-vite-template.zip`）、换 app_id，镜像/command/端口全不变（node 镜像通用，vite 自动处理 vue SFC）。

## 关键约束速查（前端项目）

| 约束 | 说明 |
|---|---|
| `vite --host 0.0.0.0` | **必须**。否则容器外（Pingora）访问 502 |
| 先 upload 再 create | 指定 app_id，预置源码，避免空 code/ 启动失败 |
| command 串联 install + vite | `sh -c "cd /app/code && npm install && npx vite --host ..."` |
| 端口 5173（dev）/ 4173（preview） | 与 `ports[].port` 一致；`expose_type=Http` |
| status=Running ≠ vite 就绪 | 看日志 `VITE ready` 或访问返回 200 判断 |
| 单 HTTP 端口 | 一个 app 只支持 1 个 HTTP 端口对外 |
| access 只返 path | host（Pingora 入口 `8089`）由调用方拼 |

## Docker Compose（本文）vs K8s（测试环境）

| 维度 | Docker Compose（✅ 实测） | K8s（⏳ 测试环境） |
|---|---|---|
| rcoder 入口 | `127.0.0.1:8090`（API）/ `8089`（Pingora） | rcoder Service（如 `8290`） |
| 计算单元 | 单容器 `rcoder-app-{id}` | Deployment + ClusterIP Service |
| 存储 | bind mount `app-workspace/{id}/` | per-app PVC（**需 CephFS**） |
| Pingora 目标 | container_ip:5173 | `{id}-svc:5173`（FQDN） |
| 访问 path | `/proxy/apps/{id}/5173/`（**同**） | `/proxy/apps/{id}/5173/`（**同**） |

**关键**：REST 契约两端完全一致，本文的 curl 脚本可直接搬到 K8s，**只换 rcoder 入口地址**。K8s 模式 per-app PVC 需集群有 ceph-csi + CephFS 后端（本地 devspace 无，故本地验证走 Docker Compose）。
