# 6. 快速开始：发布与访问

> 面向 Java 调用方的实操指南。读完你会知道：**怎么把应用发布到 RCoder** + **部署后怎么访问应用**。

## 概述

两条主线：
1. **应用发布**：选运行时镜像 → 上传应用文件 → 创建应用 → 轮询就绪 → 更新
2. **应用访问**：GET 拿 access path → 拼 Pingora 入口 → 访问应用

> **RCoder 不构建镜像**。你提前准备完整镜像地址（含 registry）+ upload 应用文件（jar/zip/脚本）+ 传启动命令。初期不限定镜像列表，推荐预构建运行时镜像（Java/Python/Node/Go/Rust）。

---

## 主线一：应用发布

### Step 1: 准备镜像（完整地址 + 提前 push）

RCoder **不构建镜像**。你提前准备好镜像，push 到 registry，create 时传**完整镜像地址**（含 registry，如 `registry.example.com/app-runtime-java:v1.0.0`）。

初期不限定镜像列表（任意完整地址均可），推荐使用预构建的运行时镜像：

| 运行时镜像 | 语言 | 预装工具 |
|---|---|---|
| `app-runtime-java` | Java 17 | Maven, Gradle, Arthas |
| `app-runtime-python` | Python | pip |
| `app-runtime-node` | Node.js / TypeScript | npm |
| `app-runtime-go` | Go | go |
| `app-runtime-rust` | Rust | cargo |

### Step 2: 上传应用文件

upload 你的应用文件（jar/zip/脚本/配置）到 app 的 `code/` 目录——这是应用启动所需的文件：

```bash
# 单文件（如 app.jar）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/upload" \
  -F "file=@./app.jar" -F "target=code/app.jar"

# 压缩包（zip/tar.gz，自动解压 + 保留目录结构）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/upload" \
  -F "file=@./dist.zip" -F "target=code/"
```

- **魔数判断**：zip/tar.gz 自动解压；其它按单文件存（不看后缀）。
- **target**：app 根相对路径。单文件=文件路径（`code/app.jar`）；压缩包=解压目录（`code/`）。
- **安全**：zip slip 防护 + 1GiB 解压限制。
- 详见 [02-接口手册 upload](./02-接口手册.md#post-appsapp_idupload--上传文件--压缩包自动判断)。

### Step 3: 创建应用

```bash
curl -X POST "$RCODER/api/v1/apps" -H 'Content-Type: application/json' -d '{
  "app_id": "app-order-svc",
  "name": "order-service",
  "image": "registry.example.com/app-runtime-java:v1.0.0",
  "command": ["java", "-jar", "/app/code/app.jar"],
  "env": { "SPRING_PROFILES_ACTIVE": "prod" },
  "ports": [{ "name": "http", "port": 8080, "expose_type": "Http" }],
  "health_check": { "check_type": "Http", "path": "/actuator/health", "port": 8080 },
  "resources": { "cpu": "1", "memory": "1Gi" }
}'
```

- **app_id 可自定义**（`app-` + DNS-1123，如 `app-order-svc`），或不传让 RCoder 自动生成。
- **创建是异步的**：立即返回 `status: Starting`，不等 Pod Ready。
- **重复 app_id → 409**（防止覆盖）。

### Step 4: 轮询就绪

```bash
# 轮询（间隔 3-5s）
curl "$RCODER/api/v1/apps/app-order-svc" | jq '.data.status'
# Starting → Starting → Running
```

- `status=Running` = 就绪。
- `status=Error` + `conditions[].reason` = 失败原因（CrashLoopBackOff / ImagePullBackOff）。

### Step 5: 更新应用

**全量替换**——传完整新 desired（`image` 必填）：

```bash
# 拿当前 resource_version（乐观锁）
RV=$(curl -s "$RCODER/api/v1/apps/app-order-svc" | jq -r '.data.resource_version')

# 更新（传完整 desired + expected_resource_version）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/update" -H 'Content-Type: application/json' -d "{
  \"image\": \"registry.example.com/order-service:v3\",
  \"command\": [\"java\", \"-jar\", \"/app/code/app.jar\"],
  \"ports\": [{ \"name\": \"http\", \"port\": 8080, \"expose_type\": \"Http\" }],
  \"expected_resource_version\": \"$RV\"
}"
```

- **乐观锁**：传 `expected_resource_version`（从 GET 拿），不匹配 → `409 ERR_CONFLICT`（防并发覆盖）。不传 = 不校验。
- **image 必填**：RCoder 无状态，不记得旧 image。

### Step 6: 停止 / 重启 / 删除

```bash
# 停止（scale=0，资源保留）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/stop"

# 启动（scale=1）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/start"

# 重启（rollout）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/restart"

# 删除（默认保留数据）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/delete"

# 删除 + 清数据（purge）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/delete" -H 'Content-Type: application/json' -d '{ "purge": true }'
```

## 主线二：应用服务访问

### Step 1: 拿访问地址

```bash
curl "$RCODER/api/v1/apps/app-order-svc" | jq '.data.access'
```

响应：
```json
{
  "external": {
    "http": "/proxy/apps/app-order-svc/8080",
    "tcp": []
  },
  "internal": {
    "domain": "rcoder-app-app-order-svc-svc.rcoder-dev.svc.cluster.local",
    "ports": [{ "name": "http", "port": 8080 }]
  }
}
```

- `access.external.http` = **path**（不含 host）。你拼上 Pingora 入口。
- `access.internal.domain` = 集群内 FQDN（同集群互调用）。

### Step 2: 访问应用

拼上 Pingora 入口 host（你持有），直接访问：

```bash
# 完整 URL = {你已知的 Pingora 入口} + {access.external.http} + {应用内路径}
curl http://10.0.0.5:8088/proxy/apps/app-order-svc/8080/api/users
# → Pingora 按 (app_id, port) 路由 → 转发到 app-order-svc:8080/api/users
```

### Step 3: Pingora 路由原理

```
客户端 ──HTTP──> Pingora（RCoder 内置，端口 8088）
                   /proxy/apps/{app_id}/{port}/{path}
                   ↓ 按 (app_id, port) 查 app_backends
                   ↓
                  应用后端（K8s: {app_id}-svc:{port}；Docker: container_ip:{port}）
```

- **按 app_id 路由**：同端口（8080）多个 app 不冲突——app_id 区分。
- **未注册 → 502**：app_id/port 没注册（app 不存在/端口不对）→ 502，Fail Fast。
- **RCoder 是唯一 HTTP 入口**：所有应用流量经 Pingora，便于统一鉴权/限流（未来）。

## 流程图

```
Java CI                          RCoder                         应用
─────────                    ────────────────                  ──────
build image ──push──→ registry
                                ↑
upload code/zip ──POST──→ /apps/{id}/upload（解压）
                                ↓
create app ───POST──→ /apps { app_id, image, ports }
                                ↓ 创建 K8s Deployment + Service
                                ↓ 注册 Pingora backend
                                ↓ 返回 access
poll ───────GET──→ /apps/{id} → Starting → Running
                                ↓
                                ↓    客户端访问：
                                ↓    http://{Pingora}:8088/proxy/apps/{app_id}/{port}/{path}
                                ↓                                    ↓
                                ↓                          Pingora → 应用后端:{port}
```

## FAQ

**Q: RCoder 帮我 build 镜像吗？**
A: 不。你自己 build + push 到 registry，RCoder 只消费 `image` 引用。

**Q: 部署后怎么访问？**
A: `GET /apps/{id}` 拿 `access.external.http`（`/proxy/apps/{app_id}/{port}`），拼上 Pingora 入口 host 就是完整 URL。

**Q: 并发 update 会冲突吗？**
A: 会（last-write-wins）。传 `expected_resource_version`（乐观锁）→ 冲突返 `409 ERR_CONFLICT`，Java 重试。不传 = 不校验。

**Q: 删除应用后数据还在吗？**
A: 在。`delete` 默认保留数据（`purge=false`）。用 `POST /apps/{id}/storage/delete` 显式清空（仅 app 已 delete 时允许）。用同 app_id 重新 create 可挂回旧数据（误删找回）。

**Q: app_id 可以用业务名吗？**
A: 可以。`POST /apps` 传 `app_id: "app-order-svc"`（`app-` + DNS-1123）。不传则自动生成 `app-xxxxxxxx`。

**Q: 上传的文件在哪？**
A: app 根目录下 `code/`（代码）、`data/`（数据）、`logs/`（日志）。upload 的 target 是 app 根相对（如 `code/app.jar`）。

## 关键约束速查

| 约束 | 说明 |
|---|---|
| HTTP 只用 GET + POST | 部署网关限制；写操作动词进 path（`/delete`、`/update`） |
| 单 HTTP 端口 | 一个 app 只支持 1 个 HTTP 端口对外 |
| TCP 初期不对外 | TCP 端口（如 PG）仅集群内 ClusterIP 访问 |
| image 必填 | update 必须传 image（RCoder 无状态不记得旧值） |
| access 只返 path | host（Pingora 入口）由 Java 拼 |
| 错误码看 code 字段 | 不看 HTTP 状态码（同一 HTTP 码可能对应多个 code） |
| resource_version 乐观锁 | K8s 有；Docker 无（开发环境不校验） |
