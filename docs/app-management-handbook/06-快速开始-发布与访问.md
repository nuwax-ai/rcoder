# 6. 快速开始：发布与访问

> 面向 Java 调用方的实操指南。读完你会知道：**怎么把应用发布到 RCoder** + **部署后怎么访问** + **生命周期/删除/销毁**。
>
> 本文聚焦**核心业务主流程**；观测/文件/存储/数据库等辅助接口见文末[附录](#附录辅助接口)。

## 概述

RCoder 是**无状态的应用 Pod 引擎**：你持有 desired（应用元数据），RCoder 现场观测 observed（运行状态）。两条主线：

1. **应用发布**：准备镜像 →（可选）上传文件 → 创建应用 → 轮询就绪 → 更新
2. **应用访问**：GET 拿 access path → 拼 Pingora 入口 → 访问应用

> **RCoder 不构建镜像**。当前 userApp 统一**单一 app-runtime 运行时镜像**（测试/生产各一份，
> 由部署 env `RCODER_RUNTIME_IMAGE_DIGEST` 注入，与发布链同源）——**create 时通常无需传 `image`**，
> 平台自动用当前环境的默认镜像；显式传入仅用于临时灰度特殊版本。

## 主线一：应用发布

### Step 1: 准备镜像（完整地址 + 提前 push）

```
nuwax-docker-images-registry.cn-hangzhou.cr.aliyuncs.com/{namespace}/{image}
```

- **命名空间区分环境（随后端走，不能混用）**：
  - K8s 模式：`nuwax-k8s-test`（测试）/ `nuwax-k8s-prod`（线上）
  - Docker Compose 模式：`nuwax-test`（测试）

> **统一运行时镜像 `app-runtime` 基于 `app-runtime-base`（rust:1.97 / Debian bookworm 底），单容器内置 PostgreSQL + pgweb（Web UI 操作数据库）+ ttyd（命令行终端）+ Node/Python/Java/Go/Rust 全语言工具链**，经 pingora path 访问，PG 数据持久化到 workspace（删容器不丢）。数据库部署详见 [08-带数据库的应用部署](./08-带数据库的应用部署.md)。

| 运行时镜像 | 语言（全有） | 测试地址（nuwax-k8s-test） |
|---|---|---|
| `app-runtime` | Node/Python/Java/Go/Rust | `.../nuwax-k8s-test/app-runtime` |

> `...` = `nuwax-docker-images-registry.cn-hangzhou.cr.aliyuncs.com`。也可本地构建：`bash docker/app-runtime-base/build.sh`（自动先 base 后 runtime → `app-runtime:latest`）。

### Step 2:（可选）上传应用文件

upload 应用文件（jar/zip/脚本/配置）到 app 的 `code/` 目录：

```bash
# 单文件
curl -X POST "$RCODER/api/v1/apps/app-order-svc/upload" \
  -F "file=@./app.jar" -F "target=code/app.jar"

# 压缩包（zip/tar.gz 自动解压 + 保留目录结构）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/upload" \
  -F "file=@./dist.zip" -F "target=code/"
```

- **魔数判断**：zip/tar.gz 自动解压；其它按单文件存。
- **target**：app 根相对路径（`code/app.jar` 单文件 / `code/` 解压目录）。
- 详见[附录 · 文件管理](#文件管理)。

### Step 3: 创建应用（异步）

```bash
# image 可省略——缺省 = 平台默认运行时镜像（env RCODER_RUNTIME_IMAGE_DIGEST，环境自适配）
curl -X POST "$RCODER/api/v1/apps" -H 'Content-Type: application/json' -d '{
  "app_id": "app-order-svc",
  "name": "order-service",
  "command": ["java", "-jar", "/app/code/app.jar"],
  "env": { "SPRING_PROFILES_ACTIVE": "prod" },
  "ports": [{ "name": "http", "port": 8080, "expose_type": "http" }],
  "health_check": { "check_type": "http", "path": "/actuator/health", "port": 8080 },
  "resources": { "cpu": "1", "memory": "1Gi" }
}'
```

- **app_id 可自定义**（`app-` + DNS-1123，如 `app-order-svc`），或不传自动生成。
- **创建是异步的**：立即返回 `status: Starting`，不等 Pod Ready。
- **重复 app_id → 409** `ERR_APP_ALREADY_EXISTS`（防止覆盖）。
- 响应 `AppInfo` 含完整 desired + `access`（访问地址）。

### Step 4: 轮询就绪

```bash
# 轮询（间隔 3-5s）
curl "$RCODER/api/v1/apps/app-order-svc" | jq '.data.status'
# Starting → Starting → Running
```

- `status=Running` = 就绪。
- `status=Error` + `conditions[].reason` = 失败原因（CrashLoopBackOff / ImagePullBackOff）。
- 响应 `AppRuntimeInfo` 含 `health`（健康信息，阶段1 合并：`health.status` / `health.instance.ready`）。

### Step 5: 更新应用（全量替换 + 乐观锁）

```bash
# 拿当前 resource_version（乐观锁）
RV=$(curl -s "$RCODER/api/v1/apps/app-order-svc" | jq -r '.data.resource_version')

# 更新（传完整 desired + expected_resource_version）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/update" -H 'Content-Type: application/json' -d "{
  \"image\": \".../app-runtime:v2\",
  \"command\": [\"java\", \"-jar\", \"/app/code/app.jar\"],
  \"env\": { \"SPRING_PROFILES_ACTIVE\": \"prod\", \"X\": \"y\" },
  \"ports\": [{ \"name\": \"http\", \"port\": 8080, \"expose_type\": \"Http\" }],
  \"expected_resource_version\": \"$RV\"
}"
```

- **全量替换**：传完整新 desired（`image` 必填，RCoder 无状态不记得旧值）。
- **乐观锁**：`expected_resource_version` 不匹配 → `409 ERR_CONFLICT`。不传 = 不校验（Docker 模式忽略）。
- **SSA 幂等**：重复发相同 update 结果一致。

### Step 6: 生命周期（停止/启动/重启）

```bash
curl -X POST "$RCODER/api/v1/apps/app-order-svc/stop"     # 停止（scale=0，资源保留）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/start"    # 启动（scale=1）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/restart"  # 重启（rollout）
```

状态机：`Starting → Running →（stop）→ Stopped →（start）→ Running`。详见 `GET /apps/{id}` 的 `status`。

### Step 7: 删除 / 清空 / 销毁（三档）

```bash
# ① 删除计算资源，保留数据（默认）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/delete" -H 'Content-Type: application/json' -d '{}'

# ② 删除 + 清空内容（purge=true，留 PVC/目录可恢复）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/delete" -H 'Content-Type: application/json' -d '{ "purge": true }'

# ③ 彻底销毁 PVC/目录（destroy，高危·不可逆·释放配额）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/storage/destroy" \
  -H 'Content-Type: application/json' -d '{ "confirm": "app-order-svc" }'
```

| 操作 | 计算资源 | 数据内容 | PVC/目录 | 配额 | 可恢复 |
|---|---|---|---|---|---|
| `delete`（默认） | 删 | 保留 | 保留 | 占用 | 是（同 app_id 重建挂回） |
| `delete {purge:true}` | 删 | 清空 | 保留 | 占用 | 否（空 PVC） |
| `storage/clear` | — | 清空 | 保留 | 占用 | 否（空 PVC） |
| `storage/destroy` | — | — | **删** | **释放** | **否（不可逆）** |

- **destroy 安全约束**：① app 必须已 delete（否则 `409 ERR_INVALID_STATE`）② `confirm == app_id`（否则 `400 ERR_VALIDATION`）③ PVC 名白名单（只删 `rcoder-app-{id}-workspace`）。
- **destroy 幂等**：PVC 已删再 destroy 也返成功。
- **K8s vs Docker**：K8s destroy 删 PVC+subvolume（释放配额）；Docker destroy 删 `app-workspace/{id}` 目录。

## 主线二：应用服务访问

> **workspace 多项目应用**（`userapp-workspace-template`）经容器内 **pingap** 统一 **:3000** 入口
> （`/`→前端兜底、`/api/`→后端），只暴露一个 HTTP 端口（`[deploy].ports` app=3000）；访问方式同下，
> port 取 3000。pingap 配置由 file-server 据 `[[projects]].proxy_path` 自动生成，详见
> [UserApp 开发设计](../userapp-development-design.md) §6.4。

### Step 1: 拿访问地址

```bash
curl "$RCODER/api/v1/apps/app-order-svc" | jq '.data.access'
```

```json
{
  "external": { "http": "/proxy/apps/u6/app-order-svc/8080", "tcp": [] },
  "internal": { "domain": "rcoder-app-app-order-svc-svc.nuwax-k8s-dev.svc.cluster.local", "ports": [...] }
}
```

- `access.external.http` = **path**（不含 host）。拼上 Pingora 入口。
- `access.internal.domain` = 集群内 FQDN（同集群互调）。

### Step 2: 访问应用

```bash
# 完整 URL = {Pingora 入口} + {access.external.http} + {应用内路径}
curl http://{Pingora入口}/proxy/apps/u6/app-order-svc/8080/api/users
# → Pingora 按 (app_id, port) 路由 → 转发到应用后端
```

- **按 (app_id, port) 路由**：同端口多 app 不冲突。
- **未注册 → 502**（app 不存在/端口不对）。
- **RCoder 是唯一 HTTP 入口**：所有应用流量经 Pingora。

### Step 3: Pingora 路由原理

```
客户端 ──HTTP──> Pingora（RCoder 内置）
                   /proxy/apps/{user_id}/{app_id}/{port}/{path}
                   ↓ 按 (app_id, port) 查 app_backends
                  应用后端（K8s: {app_id}-svc:{port}；Docker: container_ip:{port}）
```

> ⚠️ rcoder 重启后读路径的 `external.http` 可能变 `null`（HTTP 端口靠内存 `pingora_ports` 补全，重启即丢）。**以 create 响应地址为准或自行缓存**。

## FAQ

**Q: RCoder 帮我 build 镜像吗？**
A: 不。你自己 build + push，RCoder 只消费 `image`。

**Q: 部署后怎么访问？**
A: `GET /apps/{id}` 拿 `access.external.http`，拼 Pingora 入口 host。

**Q: 并发 update 冲突？**
A: 传 `expected_resource_version`（乐观锁）→ 冲突返 `409`。不传 = 不校验。

**Q: 删除后数据还在吗？**
A: `delete` 默认保留（`purge=false`）。要清内容用 `storage/clear`（留 PVC）或 `delete {purge:true}`；要彻底销毁释放配额用 `storage/destroy`（删 PVC，不可逆）。

**Q: app_id 用业务名？**
A: 可以（`app-` + DNS-1123）。不传则自动生成。

**Q: 重启应用用 `/restart` 还是 delete+recreate？**
A: 用 `/restart`（滚动，卷不 unstage，~5s）。`delete`+同 app_id 重建会触发 CephFS PVC re-stage（ceph-csi `NodeStageVolume` 重挂，~60s），慢且只用于「误删找回」DR 路径。

## 关键约束速查

| 约束 | 说明 |
|---|---|
| HTTP 只用 GET + POST | 写操作动词进 path（`/delete`、`/update`、`/storage/destroy`） |
| 单 HTTP 端口对外 | 一个 app 1 个 HTTP 端口对外；TCP 仅集群内 |
| image 必填 | update 必须传 image（RCoder 无状态） |
| access 只返 path | host（Pingora 入口）由 Java 拼 |
| 错误看 `code` 字段 | 不看 HTTP 状态码 |
| destroy 不可逆 | 三重保护（app 已 delete + confirm=app_id + PVC 名白名单） |

# 附录：辅助接口

> 以下接口非核心发布主流程，按需使用。完整字段详见 [02-接口手册](./02-接口手册.md)。

## 观测接口

```bash
# 多服务文件日志快照
curl -X POST "$RCODER/api/v1/apps/app-order-svc/logs/query" \
  -H 'Content-Type: application/json' -d '{"tail":100}'

# 日志实时流（POST SSE）
curl -N -X POST "$RCODER/api/v1/apps/app-order-svc/logs/stream" \
  -H 'Content-Type: application/json' -d '{"tail":100}'

# 健康状态（HealthInfo）
curl "$RCODER/api/v1/apps/app-order-svc/health"

# 资源使用（CPU/内存，K8s 需 metrics-server）
curl "$RCODER/api/v1/apps/app-order-svc/stats"

# 应用事件（K8s events）
curl "$RCODER/api/v1/apps/app-order-svc/events"
```

- `logs/query` 返回按 service/source 聚合的文件日志和 opaque cursor。
- `logs/stream` 是 POST SSE；前端使用 `fetch + ReadableStream`，断线后在 body 中携带 checkpoint cursor。
- `health` 返回 `HealthInfo`（status/instance/probes）。
- `stats` 的 CPU/内存需 metrics-server，否则默认空值；`restart_count` 始终可靠。

## 文件管理

```bash
# 上传（单文件 / 压缩包自动解压）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/upload" -F "file=@./app.jar" -F "target=code/app.jar"

# 列出文件（path 默认 app 根）
curl "$RCODER/api/v1/apps/app-order-svc/files?path=code"

# 删除文件
curl -X POST "$RCODER/api/v1/apps/app-order-svc/files/delete" -H 'Content-Type: application/json' -d '{ "path": "code/app.jar" }'
```

- **路径契约**：target/path 一律 app 根相对（`code/app.jar`）。path traversal 防护（`..`/绝对路径拒绝）。
- **目录约定**：`code/`（代码）、`data/`（数据）、`logs/`（日志）。
- **upload 安全**：zip slip 防护 + 1GiB 解压限制。

## 持久存储管理

```bash
# 查单个 app 存储（O(1) stat）
curl "$RCODER/api/v1/apps/app-order-svc/storage"
# → { exists, path, modified_at, is_orphan }

# 分页查询存储（强制分页，无全量模式）
curl -X POST "$RCODER/api/v1/apps/storage/query" -H 'Content-Type: application/json' -d '{
  "page": 1, "page_size": 20,
  "filters": { "orphan_only": true, "app_ids": ["app-order-svc"] }
}'

# 清空内容（留 PVC，可恢复；仅 app 已 delete 后允许）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/storage/clear"

# 销毁 PVC（高危·不可逆·释放配额；需 confirm=app_id，仅 app 已 delete 后允许）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/storage/destroy" -H 'Content-Type: application/json' -d '{ "confirm": "app-order-svc" }'
```

- `storage/query` 的 `orphan_only=true` = 只返回有数据无运行 app 的孤儿（对账用）。
- `is_orphan` 始终返回（无运行 app = true）。
- **不含 size_bytes**（CephFS 上不能用 du）。

## 数据库管理（仅 app-runtime 镜像带 PG 的 app）

```bash
# 重置 PG 密码（exec 容器内 psql，本地 trust 绕过当前密码）
curl -X POST "$RCODER/api/v1/apps/app-order-svc/db/reset-password" -H 'Content-Type: application/json' -d '{ "new_password": "NewSecret123" }'

# 新建 PG 库
curl -X POST "$RCODER/api/v1/apps/app-order-svc/db/create-database" -H 'Content-Type: application/json' -d '{ "database": "orders_db", "owner": "app" }'
```

- 仅 app-runtime 镜像（带 PG）的 app 可用；无 PG 的 app → `400 ERR_OPERATION_NOT_SUPPORTED`。
- **reset-password 解决「忘记密码进不去 pgweb」的循环依赖**（pgweb 要当前密码，rcoder exec 免密改）。
- 日常 DB 操作（建表/查改）用户在 pgweb 自助；这俩接口只覆盖 pgweb 做不到的。
- 详见 [08-带数据库的应用部署](./08-带数据库的应用部署.md)。
