# UserApp 应用迁移与凭据记录

`run.migrate` 是应用作者维护的启动前置脚本。非零退出、超时、迁移取消或程序创建失败会记录原因、退出状态和完整输出，然后继续启动同一服务。迁移失败不表示成功，服务与操作成功仍以实际启动和就绪结果为准。

旧迁移回执中的 false、损坏或不完整内容仅作诊断，不再阻止 Start、Restart、Deploy 或恢复。新请求可以重新执行未确认迁移，应用作者负责幂等性。稳定 execution.lock 保留；无法取得执行锁时不会无锁执行。已取消整个启动的 Stop 仍优先，旧进程清理未确认也保留对应物理执行保护。

迁移输出追加到服务 runtime.out.log/runtime.err.log，并按原操作及 service_id 进入日志事件。普通日志和 HTTP/SSE 展示裁剪密码；内部 operations/*.json 与部署回执保留实际 PG 凭据，以私有文件权限原子发布，用于排查与恢复。新显式输入优先，空密码或不完整新输入仍被拒绝，不使用默认密码或修改数据库账号。

旧版本记录的 password 空串是脱敏形态，不能作为实际空密码证据。旧记录不被补写成猜测的密码；恢复仅用当前有效输入或合法无 PG 的业务配置。密码指纹/HMAC审计以后单独设计，本轮不实现。

应用迁移策略不改变 database/ SQL机制、独立平台数据库命令未知结果保护、工作区边界或原操作身份。源码修改和组件测试不表示已更新运行镜像；app-cli内嵌镜像必须重建、核验实际版本并部署，发布及部署结果单独记录。
