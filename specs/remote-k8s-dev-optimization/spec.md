# Remote K8s 开发验证体验优化规范

日期：2026-09-16。状态：待实施。本目录是改造交接方案，不是完成报告。

## 1. 目标

继续以 Mac 工作目录（含未提交修改）为输入，在个人双节点 Linux K8s 上构建、部署并验证 RCoder。减少重复构建与整套重跑，允许开发者在一轮测试开始后继续编辑，同时保证结果始终对应明确的源码、测试和镜像身份。

现有入口、配置与隔离约束继续有效：`make remote-k8s-*`、Python 工具、`.env.local`、Mutagen 单向同步、独立 namespace、digest 部署、环境锁、资源所有权及 PVC 保留。

## 2. 当前事实

以实施前再次读取的源码为准，本方案检查时：

- `tools/remote_k8s/main.py::build` 每轮解析基础镜像、创建快照并依次构建 rcoder/computer/runtime。
- Dockerfile 已有 Cargo/BuildKit 缓存；不是完全无缓存。`COPY . .` 和对所有 `.rs` 的 touch 仍使增量体验受限。touch 用于防止缓存误判并复制旧二进制，不能直接删除。
- 服务端在远端固定快照构建；UserApp/Chat 启动器仍读取本地活动工作目录，并校验其漂移。
- `tests-e2e/tools/run.py` 内部支持过滤；远端入口尚未提供场景参数。UserApp 启动器是一条有依赖的完整生命周期链，不能任意跳过中间步骤。
- doctor 为前置检查；logs 部分采集错误被忽略，没有完整的逐项诊断结论。
- 测试结束时校验 deployment receipt 的长期外部资源基线，合法的集群维护也可能触发失败，不能未经检查自动覆盖该基线。
- 个人集群 Gateway 已在 2026-09-16 修复，随后按用户要求卸载 worker 的 Tailscale；见相邻 `remote-k8s-dev/gateway-repair-2026-09-16.md`。当前状态须现场验证，不能把旧报告当新结果。

## 3. 本次必做范围

### R1 固定测试快照

- 测试开始时冻结完整可执行测试输入：源码、启动器、fixtures、Cargo manifests/lock、构建脚本与必要配置文件。
- 无需用户 Git commit；不得修改主工作目录的 HEAD/index、覆盖并行开发改动。
- 冻结成功后，原工作目录可继续修改。只允许明确归属本轮的测试快照执行，不能仅删除漂移断言。
- 测试快照自身发生修改、新增可执行输入、删除或链接逃逸，应失败。
- 原目录变化仅记为提示；冻结期间变化重试或明确失败。
- 记录服务端源码摘要与测试摘要，二者不一致时明确展示。快照/报告不能静默消失；生成结果不能反过来污染源码校验。

### R2 可证明正确的构建复用

- 同一有效构建输入、工具链、平台、基础镜像与构建参数可复用已成功产物，不必重复编译和推送。
- 基础镜像或工具链用可验证 digest 纳入身份；cache miss、产物不存在则正常重建，仓库认证/连接错误不得当作命中或成功。
- 第一阶段允许保守地对完整源码摘要复用；随后仅在证明输入闭包完整后排除无关文档，并按镜像目标复用。
- 任何无法判断的依赖变化按受影响处理。禁止仅按文件后缀或 git diff 推断依赖：Rust include_str/include_bytes、build.rs、workspace/path dependency 都可能读取额外文件。
- receipt 同时保留本轮请求身份、实际产物来源及复用理由，不能给旧镜像伪造新构建记录。

### R3 场景筛选与失败重跑

- Chat 支持筛选独立场景；空匹配、未知场景、非法组合在业务执行前失败。
- UserApp 先保留整链；只有显式定义独立 fixture、前置和清理边界后才允许分组。
- 失败重跑只处理具备可靠场景结果的失败集合，使用原冻结测试输入，记录父报告与新报告。原报告不可改写。
- 校验部署 UID/generation/digest 及适用的子运行时镜像身份；部署变化应拒绝旧结果重跑，提示发起新轮次。
- 无可靠场景结果的构建/环境/aborted 失败，不猜测“失败用例”；明确要求修复后重新运行对应入口。
- 筛选测试通过须标记为部分覆盖；不能改写成全套通过。

### R4 状态、分层检查、诊断

- status 只读，展示已部署身份、入口、实际就绪状态、最近测试及其关联版本；旧报告明显标为历史结果。
- check 分项检查直连、Gateway 两节点请求、控制面、DNS与存储健康；缺权限/未知/超时独立记录，不能当通过。
- 默认不创建资源；需要 Pod 内探测的检查提供显式模式、资源归属和清理协议，不冒充只读检查。
- 日志采集按项继续，完整记录错误和耗时；不能因单项失败丢失其他诊断，不能吞掉原始测试错误。
- 每个外部调用有 deadline，整体检查也有预算；凭据不出日志。
- 不将测试期间修改外部资源的保护取消。长期基线与本轮基线应分开；若新增显式 rebaseline，必须展示差异并有明确操作授权，verify/test 不得自动接受漂移。

### R5 文档与实测

- 更新 AGENTS.md、工作流 README、env.example/Make help（有新增参数时），保持 CLAUDE.md 仅导入。
- 提供验证记录：源码身份、实际命令、退出码、旧/新耗时、复用命中、业务覆盖与未完成项。
- 完成 Python 回归、Make 参数验证以及真实个人集群验收。不要用 mock AI 宣称业务通过。

## 4. 第二阶段：可选 watch

在 R1–R5 稳定后实施，不能阻塞前述交付：防抖、只保留最新待处理快照、同环境串行、不替换正在受测部署、退出不留后台任务。真实 AI watch 必须显式选择。首批不要承诺热更新或引入 Pod 内覆盖二进制。

## 5. 非目标

不迁移 Python 到 Rust，不重建个人集群，不修改业务语义、不删除 PVC，不自动提交或发布 npm；不通过关闭断言/所有权/fencing 换速度。生产 Chart 发布验收仍独立存在。
