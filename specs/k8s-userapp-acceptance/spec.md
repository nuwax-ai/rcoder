# K8s userApp 验收规范

目标：在用户明确授权的个人测试集群验证实际 userApp 跨副本链路，不以 Compose 或 API 适配器测试代替真实 K8s 证据。

- namespace 仅 `nuwax-k8s-test`；显式配置 SSH、rcoder NodePort 和代理 NodePort，检查入口属于该集群节点。
- 本次 UUID 应用名必须在创建前不存在；操作和清理均仅涉及本次登记的应用。
- 明确冲突后能够重新 ensure，不误删成功请求的资源，不遗留 builder 操作锁。
- 跨 rcoder 进程访问同一工作区、构建、查询、取消和 SSE 必须保持正确归属。
- 冷部署不传 release_id 仍能有限时间完成；A/B 制品内容和摘要可区分。
- hot 拒绝 env 变化；制品 SHA 失败后旧应用可用；成功 hot 切换到 B 且 Pod/容器身份不变。
- 部署成功具有匹配的请求/制品/操作/代次身份及持久化成功状态。
- stop 幂等；旧 Pod 完全消失后，start 创建新 UID 的 Pod 并继续服务 B。
- 空执行、必经断言缺失、任意断言失败、清理失败不能通过。后续成功不覆盖先前失败。

边界：本轮使用无第三方依赖的真实静态应用构建，不替代真实 AI、七语言工具链、数据库迁移、生产故障注入、SSE 慢消费者或完整并发矩阵验收。不修改集群权限，不对共享平台注入故障。
